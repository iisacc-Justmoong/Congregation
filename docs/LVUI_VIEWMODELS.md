# Congregation의 LVUI 뷰모델

`App/Native/EditorBackend`는 앱의 명령·관찰 가능한 표시 값과 입력을 제공한다.
Qt, QML 또는 LVRS 타입을 포함하지 않는다. 문서 편집과 저장은 기존 `Artwork`와
iiSharedCanvas가 소유하며, 뷰모델의 선택·색상·목록 상태는 저장 문서가 아니다.
캔버스 설정, 도구 설정과 타임라인 모델도 표준 C++와 iiSDK의 관찰 값을 사용한다.
이 모델들은 LVUI의 실행 중 소스 해석이나 QML 메타 객체를 요구하지 않는다.

환경설정의 General·Profile·Members 전환 버튼은 LVUI의 `method`를 통해 기존
`EditorBackend` 명령을 각각 한 번 발행한다. 탭 선택과 콘텐츠 가시성은 계속
뷰모델의 관찰 상태가 결정하며, 선택된 탭을 다시 눌러도 선택을 해제하지 않는다.
Profile 사진은 `EditorBackend.profile_avatar`가 관찰 가능한 이미지로 발행한다.
창을 열 때 기존 사진을 전달하고 사진 선택·삭제 시 같은 값을 갱신한다. LVUI
`Avatar`가 원형 자르기와 사진이 없을 때의 기본 심벌을 그리며, 바깥
`EventListener`는 기존 사진 메뉴 열기 입력을 전달한다. 사용자 이름은 LVUI
둥근 입력의 지우기 동작을 통해 같은 뷰모델에 반영한다.

`CanvasSetupModel::view_state`는 검색·카테고리·선택·치수·단위·배경·검증 결과를
한 스냅샷으로 발행한다. `view_selection()`, `view_dimensions()` 등의 읽기 함수는
해당 스냅샷을 관찰하므로 LVUI가 의존 값으로 사용할 수 있다. 새 입력이 무효이면
오류와 생성 가능 상태도 함께 바뀌고 다음 유효한 입력에서 복구된다. 창은
`changed` 콜백으로 제품의 본문과 입력 상태를 갱신한다.

## 목록과 창별 선택

`PresentationList`는 제품이 만든 행 스냅샷을 LVUI의 `ListSource`로 제공한다.
키·레이블·부모·활성·편집 가능·체크·이동 가능 상태는 제품의 `PresentationRow`에 보관한다.
LVUI 평면 목록에는 키·레이블·활성·선택 가능·편집 가능·이동 가능 상태를 투영한다. 체크와 부모는
원본 행에 남으며 평면 목록이 자동으로 그리거나 편집하지 않는다. 필요한 화면은
자체 행 구성과 명령을 명시해야 한다.
참가자 행은 읽기 전용이며 이동할 수 없다. 레이어 행은 이동 가능 상태를 제공한다.
제품은 목록의 일반 편집기를 참가자 목록이나 레이어
문서에 자동으로 연결하지 않는다. 레이어의 실제 변경과 실행 취소는 문서를 소유한
`Artwork`와 기존 명령 경계가 담당한다.

행을 바꿀 때 키와 문자열을 먼저 확인한다. 중복 키 등 잘못된 후보는 이전 원본과
투영을 유지하며, 동일한 후보는 리비전을 증가시키지 않는다. 각 스냅샷은 불변이고
변경 시 `revision`이 게시된다. `EditorBackend`는 공유된 레이어·회원 원본을 각각
`layer_source`/`member_source`와 `layer_revision`/`member_revision`으로 제공한다.
새 목록 활성화는 `activate_layer`와 `activate_member`를 통해 각각 레이어와 회원
선택 명령에 키를 전달한다.
개별 LVUI `ListController`의 선택은 원본 목록이나 파일 리비전을 변경하지 않는다.
원본은 생성 스레드에서만 변경하고 읽기 스냅샷은 소유권을 가진다. 구독은 뷰모델이
소유하며 뷰모델이 사라지면 해제한다.
공유 원본은 LVUI 뷰를 구성하기 전에 `set_presentation_lists`로 지정한다.
구성 후에는 같은 원본의 `replace`를 사용한다. 이미 생성된 LVUI `List`의 원본
포인터를 다른 객체로 바꾸는 동작은 제공하지 않는다.
제품 작업 영역의 타임라인 선택은 문서 리비전이나 목록 원본을 변경하지 않는다.
독립 LVUI 계층 목록 자체의 사용자 행 대리자와 일부 구조 편집 기능은 별도 범위다.

## 공유 색상과 화면

`EditorColor`는 LVUI `ColorSelection`과 `ColorSelectionSurface`를 소유한다.
메인 화면과 도구 상세 표면은 같은 원본 및 리비전을 사용하고, 외부 색상·알파 변경과
표면의 연속 편집은 제품 백엔드와 캔버스에 전파된다. 잘못된 색상과 다른 스레드의
변경은 거부한다. 관찰 수명은 해당 뷰모델과 위젯 세대에 귀속된다.

입력·명령 콜백은 호출 중 소유 뷰모델이 교체되어도 실행 중인 함수의 수명이 끝까지
유지되도록 복사해서 호출한다. 색상 명령은 명령을 시작한 색상 모델을 완료까지 보유한다.
목록 또는 색상 변경 알림이 다른 원본으로의 교체를 유발하면 이전 원본의 남은 게시와
대기 중인 관찰 알림은 새 원본의 상태를 덮어쓰지 않는다. 알림 처리 중 뷰모델이
퇴역한 경우에는 남은 게시도 중단한다.

설정 창과 새 캔버스 창은 열 때마다 별도의 세대 식별자를 사용한다. 닫힌 창의 늦은
열기·크기 변경·닫기 및 지연 정리 콜백은 새로 열린 창이나 뷰모델에 적용하지 않는다.
설정 화면의 상태 발행 중 창이 교체되면 이전 뷰모델의 나머지 변경을 중단한다.
LVUI의 `NativeEventListener`는 호스트에서 재진입한 입력과 캡처 취소를 순서대로
지연 처리하며, 그 상세 계약은 LVUI의 `docs/NativeEventListener.md`를 따른다.
생성된 LVUI 콜백의 여러 상태 변경은 해당 활성화의 바인딩에서 한 번에 반영된다.
Core 속성 자체의 관찰 알림과 iiGUI에 직접 연결된 제품 위젯은 각각의 기존 동기 계약을
유지한다. Core 속성의 `stats()`와 LVUI `BindingStats`는 값이나 필압을 기록하지 않고
전달 중 여부·대기·갱신 건수를 조회하는 진단 경계다.

세 선언 화면과 작업 영역은 독립 LVUI 위젯을 사용한다. 제품의 문서·협업 상태는
`PresentationList` 원본 한 곳에 게시한다. 과거 `src/App` Qt 소스는 현재 작업
트리에서 삭제 상태이며 이전 스타일 준비 스크립트는 활성 빌드에 포함하지 않는다.
LVUI 생성기·헤더와
iiGUI 라이브러리는 같은 호환 설치본을 사용해야 한다.

메인 화면의 작업 영역과 새 캔버스 선택기는 각각 LVUI 선언 안의 `NativeView`에
C++ 표면 원천을 연결한다. 원천이 구성한 위젯은 부모 LVUI 화면에 포함되지만 별도의
콘텐츠 세대에 속한다. 메인은 같은 `EditorBackend`, 새 캔버스 창은 같은
`CanvasSetupModel`을 사용한다. 세대의 소유권·실패·검증 범위는
[화면 연결 계약](LVUI_VIEW_MIGRATION.md)을 따른다.

iiGUI의 컨텍스트 메뉴와 앵커는 같은 세대에 있어야 한다. 작업 영역의 도구와
레이어는 자식 세대이고 메뉴는 부모 세대이므로, 제품 어댑터는 작업 영역에서
컨텍스트 입력을 받아 창 좌표를 메뉴 세대의 좌표로 변환한다. 기존 레이어 입력
처리기를 교체하지 않으며, 다른 입력은 그대로 전달한다. 색상·텍스트 및 상태
팝업도 세대가 다를 때 앵커 위치를 열기 시점에 변환한다. 서로 다른 세대 사이의
팝업은 열린 뒤 앵커가 움직여도 자동으로 따라가지 않는다. 같은 세대의 팝업은
iiGUI의 기존 앵커 추적을 사용한다.

작업 영역의 아이콘 버튼은 LVUI 공통 설정을 사용한다. 두 열의 도구 레일 너비와
행 높이 및 타임라인 레이어 행 높이는 이 공통 버튼의 치수와 LVUI 간격에서
계산하며, 제품이 버튼 크기나 안쪽 여백을 다시 지정하지 않는다. 도구 선택은 이전과 같이 `EditorBackend`가
소유하고 제품별 시각 설정과는 분리한다.

제품에서 iiGUI 형식의 입력 옵션을 LVUI 소유 필드에 전달할 때 `maximum_length`의
0은 문자 수 제한 없음, 양수는 Unicode 스칼라 개수로 해석한다. 단일 스칼라
이모지는 하나로 계산하며 선택 교체·조합 확정·실행 취소에도 같은 제한을 적용한다.
이 제한은 독립 LVUI의 입력 상태가 처리하고 제품 어댑터는 단위만 전달한다.
같은 어댑터는 입력의 크기를 LVUI `InputFieldSize::compact`로 선택한다. 제품은
입력별 `InputStyle`을 전달하지 않으며, 임의 스타일 입력은 명시적으로 거절한다.
이 프리셋은 원본 Figma의 공통 크기와 여백을 적용한다. 이 어댑터는 LVUI의 둥근
입력 재질과 지우기 동작도 선택한다. 지우기는 한 번의 편집이며 입력 포커스를
유지한다. 기존 선언형 화면의 입력은 별도의 표면 선택을 하지 않으므로 이 어댑터의
설정이 자동 적용되지는 않는다. LVUI 자체는 원통형과 인라인형도 제공하지만,
실제 화면의 픽셀 검증과 입력 방식별 포커스 구분은 아직 남아 있다.

## 검사

`Congregation.presentation_list`는 유효하지 않은 행과 중복 키, 불변 스냅샷,
변경 없는 게시, 스레드와 창별 선택을 검사한다. `Congregation.editor_viewmodel`은
두 뷰모델의 원본 공유, 레이어·회원 선택, 색상 변경·원본 교체와 퇴역을 검사한다.
반복 창 세대 교체 후 늦은 정리, 실행 중 콜백 교체, 관찰 알림 중 목록·색상 원본
교체 및 뷰모델 퇴역에 대한 회귀 사례도 포함한다.
`tests/fixtures/EditorViewModel.lvui`, `CanvasSetupViewModel.lvui`와
`TimelineViewModel.lvui`는 실제 뷰모델을 가져오는 독립 LVUI 생성 코드의 목록·색상·
슬라이더·캔버스 설정·타임라인 계약이다.
`Congregation.independent_main`, `independent_workspace`, `independent_setup`과
`independent_preferences`는 실제 화면 구성과 입력 경계를 창 없이 검사한다.
`independent_setup`은 입력 길이의 Unicode 스칼라 계산과 0의 무제한 의미, 공통
크기와 사용자 지정 입력 스타일 거부, 둥근 재질, 지우기와 그 실행 취소도 확인한다.
`independent_main_window`는 선언형 도구 레일과 아이콘 버튼의 공통 기하,
선택·강조 상태와 도구 명령을 확인한다. `independent_workspace`는 남은 C++
작업 영역과 타임라인의 위젯 트리를 확인한다.
`lvui_native_boundary`는 제품 소스에서 입력 스타일과 아이콘 버튼 기하의 직접
지정 및 제거한 전용 크기 선언의 재유입을 거절한다.
`independent_workspace`의 `INPUT_LOOP_TRACE`는 Core EventLoop에 주입한 포인터 작업의
제출·실행 수와 LVUI 입력·효과 수를 출력한다. 이는 iiGUI 위젯 입력을 모의한 경로이며
실제 운영체제 이벤트나 물리 펜 장치의 계측 결과는 아니다.
`independent_main_window`는 활성화·작업 화면, 최소 창 크기와 팝업의 전체 그리기
목록이 iiGUI의 레이어 및 자원 제한을 만족하는지도 확인한다. 작업 화면은 개별
위젯의 순서 보존을 위해 64개보다 많은 레이어를 사용할 수 있다.
메뉴의 Undo·Redo·복사·붙여넣기는 위젯의 구체 종류가 아니라 포커스된 텍스트 입력
기능을 확인한다. LVUI가 스택에 제공하는 텍스트 편집 중에도 캔버스 명령이 실행되지
않으며 네이티브 창 자체 검사가 이 경계를 확인한다.
네이티브 창 `--self-test`의 `NATIVE_INPUT_TRACE`는 한 Core 작업에서 주입한 33개 펜
입력과 상태 리비전·대기값을 출력하고, 스트로크 중간 픽셀을 검사한다.
`NATIVE_VIEWMODEL_TRACE`는 설정 창을 닫자마자 다시 여는 6개 활성화를 기록한다.
이 역시 실제 창과 렌더러를 사용하지만 이벤트는 합성이며 물리 장치 증거는 아니다.
빌드 및 창 없는 검사와 실제 앱·기기 실행 결과는 구분한다.

서로 호환되는 독립 SDK 스테이징을 지정해 macOS에서 생성·컴파일·창 없는 위젯
검사를 재현할 수 있다. 다음은 이 작업 공간의 경로 예시이며 앱의 이전 SDK 키트에
새 헤더를 섞어 링크하지 않는다.

```sh
python3 -B tests/verify_lvui_viewmodel.py \
  --lvui ../../SDK/LVUI \
  --iigui-source ../../SDK/iiGUI/src \
  --iigui-prefix ../../SDK/iiGUI/build/lvui-sheet-host-stage-20261029 \
  --core-prefix ../../SDK/iiSDKCore/build/lvui-observation/prefix \
  --color-prefix ../../SDK/iiColorManager/build/lvui-colors/prefix \
  --iijson-source ../../SDK/iiJson/src \
  --vulkan ../../SDK/build/congregation-native/prefix/lib/libvulkan.dylib
```

이 과거 호스트 검사 도구는 현재 macOS만 지원한다. 임시 생성물은 제품의 `build/`에
생성하고 검사 후 제거한다. 다른 운영체제에서의 빌드·입력·렌더링 및 물리 장치 실행을
이 검사로 대신하지 않는다.
