# Congregation 네이티브 ApplicationWindow

## 기준과 구현 경계

Main은 Figma `r4E0PNUdZuo6dEiMEitF2I`의 `83:6974`, Tool의 전체 항목은 `130:1832`를 기준으로 한다. 기준 클라이언트는 1999×1080이다. 2026-10-26의 변경 지시에 따라 왼쪽 에셋 사이드바를 제거하고 세로 도구 막대만 남긴다. 네이티브 앱 반영에 이어 Figma `83:6973`의 기존 뷰도 같은 구성으로 동기화했다. 캡션·윈도우 운영체제 테두리는 애플리케이션 콘텐츠에 포함하지 않는다.

`App/Native/views/Main.lvui`의 ApplicationWindow를 빌드 때 C++23으로 컴파일한다. `MainWindow`는 생성된 옵션·스코프·백엔드를 유지하면서 같은 iiGUI 위젯 세대에 `WorkspaceView`를 구성한다. 앱의 최종 진입점·이벤트 루프·프레임 루프는 iiSDKCore가 소유한다. Qt·QML·브라우저·WebView 실행기를 연결하지 않는다.

`Preferences.lvui`는 멤버 목록을 `PresentationList`와 모델 리비전 및 항목 활성화
콜백에 연결한다. 선택은 공유 목록을 수정하지 않으며, 탭의 선택 표시는 앱 상태를
따른다. `CONGREGATION_TEST_INDEPENDENT_PREFERENCES=ON`은 실제 설정 뷰를 독립
LVUI로 생성하고 헤드리스 위젯 트리에서 초기 목록, 갱신, 선택 키와 수명을 검사한다.
테스트 바이너리의 직접 동적 의존성과 공개 심볼에서도 Qt·LVRS를 찾지 못했다.
실제 앱 구성의 세 선언 화면과 작업 영역도 독립 LVUI를 사용한다. 이 검사는 실제 창
실행의 증거는 아니다.
도구 패널은 LVUI가 소유하는 버튼·체크박스·슬라이더·콤보박스를 사용한다.
제품의 기존 도구 패널 상호작용 검사를 `CONGREGATION_TEST_INDEPENDENT_TOOL_PANEL=ON`으로
재사용하며, 화면 구성은 `ToolPanel.cpp` 한 곳에서 관리한다. 포인터
슬라이더, 도구별 표시, 아이콘 및 비활성 체크박스 갱신을 헤드리스 트리에서 검사했다.
메인 작업 영역과 타임라인의 제품 소스도 독립 LVUI 컨트롤에 연결했으며 별도의
`CONGREGATION_TEST_INDEPENDENT_WORKSPACE=ON` 검사에서 주요 조작을 확인한다.
같은 옵션의 `independent_main_window`는 앱과 동일한 MainWindow 구성 함수를 호출해
인증 전후 표시 전환, 도구 선택과 색상 모델 공유를 한 위젯 트리에서 검사한다.
텍스트 도구의 여러 줄 필드에서는 자동 줄바꿈 뒤 줄 끝 이동과 편집 내용의
`EditorBackend` 전달도 확인한다. 도형 메뉴에서는 포인터 이동이 항목에 초점을 주되
실행하지 않고, 이어진 클릭이 도구 동작을 전달한 뒤 메뉴를 닫는지 검사한다. 이
검사는 OS 창을 열지 않는다.
여기서 인증 상태는 시험 모델이 지정하며 실제 계정이나 서버 확인을 뜻하지 않는다.

`EditorColor`는 LVUI `ColorSelection`과 하나의
`ColorSelectionSurface`를 공유한다. 표면 편집 콜백이 돌아온 뒤 리비전을 발행해
다른 표면과 제품 상태를 갱신하고, 외부 색상·알파 변경에도 같은 경로를 사용한다.
소유 스레드가 아닌 접근, 잘못된 색상과 알파는 거부한다. 독립 색상 검사에는 두
표면의 동기화, 연속 드래그, 이전 리비전 거부와 검정에서의 숨은 색조 보존을
포함한다. 메인 뷰, 작업 영역과 제품 백엔드가 같은 색상 모델을 사용한다.

메인 창의 WindowMaterial, 버튼, 콤보박스, 세그먼트, 슬라이더와 색상 표면은 LVUI가
소유한다. WindowMaterial에는 Figma ApplicationWindow를 측정한 대표 색을 사용하고
블러·안쪽 하이라이트·그림자를 명시적으로 끈다. 이 단색 창은 LVUI가 불투명 패널
그리기로 전달하며 각 패널은 별도 배경을 그리지 않는다. 창이 없는 검사에서 인증 전후와
최소 크기의 배경색 및 그리기 명령을 확인하며 실제 GPU 픽셀·성능 검사는 포함하지 않는다.
투명도 레일은 iiGUI의 그래픽과 포인터 입력을
사용하고 LVUI 색상 선택의 alpha 채널을 공유한다. 일반 패널은 투명하며 1px
경계선으로 구분한다. 타임라인의 격자·노출 번호·플레이헤드는 iiGUI의 보존된 그래픽으로
그린다. C++ 소유 객체와 구독은 위젯 세대에 귀속된다. 새 캔버스 창의 검색·입력·
드롭다운과 메뉴도 LVUI 경로로 옮겼으며, 동일한 제품 모델을 사용하는 헤드리스
검사에서 프리셋·검색·단위·배경·생성 조건과 좁은 화면의 메뉴를 확인했다. 본문과
갤러리는 새 위젯 세대를 확정하기 전에 함께 구성해 중첩 화면의 생성 경계를 지킨다.
`Congregation.canvas_reference`는 새 캔버스 크기와 프리셋 원본, 모달이 아닌 선언,
부모 호스트를 지정한 자식 창 연결을 소스 수준에서 검사한다. 이 검사는 실제 운영체제
창이 열리거나 동작했음을 증명하지 않는다.
앱 전체 빌드와 실제 OS 창의 검증 결과는 이 개별 검사와 구별한다.

## 패널 색과 경계선 합성

창 배경은 LVUI의 `Panel/window`를 그대로 사용하며 악센트를 합성하지 않는다. 일반 패널은 투명하다. 외곽선은 Figma와 앱에서 `Panel/canvas`를 공유하고 두께는 1px이다. 타임라인 내부 선은 `Material/Surface/Dense/Edge`를 창 배경에 합성한다. 전용 Color picker 구분선은 `Panel/surfacePanel`이다. 플레이헤드와 선택 표시는 파랑 상태 토큰을 사용한다. 창 재질의 Dense 75와 Glass 25는 별도 밀도 선택으로 유지한다.

## 도구 설정 모델

`ToolSettings`의 단일 카탈로그가 22개 이름·단위·범위·기본값·증감 단위와 위젯 구성을 제공한다. 크기는 1..1024px의 로그 축을 사용한다. 버튼은 실제 값의 한 단위를 바꾸며, 슬라이더는 정규화 값과 실제 값을 변환한다. 비정상 수치는 거부하고 범위를 넘는 유한 값은 제한한다. 기존 Figma 표시값을 기본값으로 유지한다.

설정은 문서 리비전·저장 이력과 분리된다. 저장 버튼은 `tools.ini`를 FileProvider의 스테이징·원자적 발행으로 저장한다. 불완전하거나 잘못된 설정을 읽으면 전체 적용을 거부한다.

크기·불투명도·흐름·경도·간격은 BitmapBrush로, 각도·둥글기·압력·기울기·속도·산포·안정화는 iiPaintEngine의 해당 상태로 전달한다. 혼합·물기·부하·희석과 모 수는 혼합/브리슬 도구의 조건부 설정이다. 이 값의 전달과 엔진의 모든 물리 효과 재현은 별도 검증 범위이다. End 값은 설정 모델에 보존되며 현재 스트로크 엔진에는 대응하는 후단 테이퍼 계약이 없다. Start·Taper strength는 도입 거리, Minimum size는 도입 최소 크기에 대응한다.

## 타임라인과 문서 변경

화면의 위치는 `MM:SS.mmm`로 표시하며 눈금은 현재 프레임 간격을 나타낸다. 드래그와 좌우 방향키는 프레임 경계로 이동한다. 재생은 같은 Core 프레임 루프를 사용한다. 시간 이동·선택·스크롤·탭 변경은 문서를 수정하지 않는다. 손잡이에서 Alt를 누르고 세로로 드래그하면 프레임 레이트를 조절하고, 놓을 때 문서의 시간 설정을 갱신한다.

레이어 가시성·불투명도·혼합 모드·이름·순서 변경은 Artwork를 경유하는 실제 편집이다. 이름은 레이어 행에 포커스를 둔 상태에서 Enter로 편집하고, 순서는 이름 영역을 드래그하여 바꾼다. 좌우 반전과 90도 회전은 SDK의 아핀 행렬 관례에 맞춰 캔버스 중심에 합성한다. 메뉴와 도구를 표시했다는 사실을 모든 전문 페인팅·애니메이션 기능의 구현으로 간주하지 않는다. 현재 편집기에 연결되지 않은 도구는 문서를 바꾸지 않고 지원 범위를 알리며 기존 도구 선택을 유지한다. 그룹·마스크·클리핑·레이어 잠금·키프레임 편집·어니언 스킨은 이 화면에서 비활성 상태이다. 정렬·분배·워프 등 아직 구현되지 않은 상단 명령도 문서를 수정하지 않는다.

## 에셋과 독립 실행

두 PNG는 Figma의 개별 콘텐츠 이미지이다. 전체 화면 스크린샷은 코드나 배경으로 사용하지 않는다. 플레이헤드도 원본의 두 SVG 레이어와 알파 마스크를 그대로 합성한다. 아이콘은 LVUI에 이식된 같은 이름의 원본 자산을 사용한다. `palette-menu`는 원본 컴포넌트 이름인 `generalmoreVertical`, 이미지 표식은 `fileTypesimage`에 대응한다.

원본 자산은 `resources/figma`에 있고 번들의 `Contents/Resources/figma`에 복사한다. 실행 중 소스 체크아웃이나 임시 Figma 다운로드 URL을 사용하지 않는다. 다른 플랫폼은 실행 파일 옆 `resources`를 사용한다. 기존 `AssetLibraryView` 소스는 LVUI 카드·아이콘으로 이전하고 별도로 검사하지만 현재 창에 구성하지 않으며 활성 타깃에서도 제외한다. 라이브러리 경로 설정과 Society 연동 서비스는 별도 기능으로 유지한다. 사이드바 제거 과정에서 원본 에셋과 사용자 라이브러리 폴더는 수정하지 않는다.

## 검증

2026-11-01에 Qt5·Qt6·LVRS 패키지 탐색을 끈 구성으로 macOS 앱 대상을 빌드했다.
번들 안의 Mach-O 이미지 7개와 동적 의존성 70개에서 Qt·LVRS 링크를 찾지 못했고
번들 그래프와 임시 서명을 검사했다. 이는 OS 창 실행, 렌더러별 화면 일치 또는
서명·공증된 배포 결과를 뜻하지 않는다. 독립 LVUI 화면의 창 없는 검사는 각 화면의
모델 연결과 위젯 상호작용을 검증한다.

2026-11-02에는 단색 창 설정과 하위 트리 장면 API를 포함한 iiGUI를 반영해 앱 전체
개발 빌드와 관련 헤드리스 검사 12건이 통과했다. 인증 전후와 1999×1080·1200×720 호스트에서 불투명 창 색상과
효과 없는 그리기 명령을 확인했다. 개발 번들의 Mach-O 7개와 동적 의존성 항목
70개에서 Qt·LVRS 링크를 찾지 못하고 로컬 임시 서명을 확인했다. 주 실행 파일의
SHA-256은 `f73b3b658fbbec8fb67a4642dc48048d12a3f16e2919bcea6c973dc165fb5b67`이다.
기존 빌드 캐시를 재사용했으며 GUI와 GPU를 실행한 결과는 아니다.

이어지는 iiGUI 장면 그래프·Metal 소스 변경을 반영한 전체 개발 빌드와 관련
헤드리스 검사 12건도 통과했다. 개발 번들의 Mach-O 7개와 동적 의존성 70개,
주 실행 파일 공개 심볼 10,200개에서 Qt·LVRS 링크나 해당 공개 이름을 찾지 못했고
로컬 임시 서명을 확인했다. 이 빌드의 주 실행 파일 SHA-256은
`4cabb1800b37f1432869b770d38256927e22a9fdf8d714510c8da4627d76b595`이다.
이 검사는 사용자에게 설치된 앱, 실제 창·GPU 픽셀 또는 숨겨진 정적 코드 전체의
부재를 증명하지 않는다. 기존 빌드 캐시를 재사용했다.

이후 Vulkan 장면 합성 및 자동 렌더러 선택 변경을 반영해 전체 개발 빌드와 관련
헤드리스 검사 12건이 통과했다. 개발 번들의 Mach-O 7개, 동적 의존성 항목 70개와
주 실행 파일의 공개 심볼 10,200개에서 Qt·LVRS 링크나 해당 공개 이름을 찾지
못했으며 로컬 임시 서명을 확인했다. 주 실행 파일의 SHA-256은
`6aa40ca6beca76741201f18d1f71e7ed44149ff925c36b183e2a7344c63d00f0`이다.
기존 빌드 캐시를 재사용했으며 설치된 앱, 숨겨진 정적 코드 전체의 부재, 실제 창이나
GPU 출력을 검증한 결과는 아니다.

위젯의 자동 재질 소스 연결을 포함한 iiGUI·LVUI 스테이징으로 다시 빌드한
개발 앱과 관련 헤드리스 검사 12건이 통과했다. 개발 번들의 Mach-O 7개,
동적 의존성 항목 70개와 주 실행 파일 공개 심볼 10,200개에서 Qt·LVRS 링크나
해당 공개 이름을 찾지 못했고 로컬 임시 서명을 검증했다. 주 실행 파일의
SHA-256은 `c61ff5a44733ac85ab6e408e80b3287295a481a4dfad7096f35da41488cccdc2`이다.
현재 제품 화면에서 새 재질 소스 입력을 직접 사용하는 곳은 찾지 못했으므로 이
검사는 기존 화면의 회귀 검사다. 기존 빌드 캐시를 사용했으며 실제 창·GPU 출력,
설치된 앱이나 숨겨진 정적 코드 전체의 부재를 검증하지 않았다.

Direct3D 11의 장면 합성을 추가한 iiGUI 스테이징으로 개발 앱을 다시 빌드하고
관련 헤드리스 검사 12건을 통과했다. 개발 번들의 Mach-O 7개, 동적 의존성 항목
70개와 주 실행 파일 공개 심볼 10,200개에서 Qt·LVRS 이름을 찾지 못했으며 로컬
임시 서명을 확인했다. 주 실행 파일 SHA-256은
`c61ff5a44733ac85ab6e408e80b3287295a481a4dfad7096f35da41488cccdc2`이다.
기존 빌드 캐시를 재사용했고 Xcode가 중복 실행 검색 경로를 경고했다. 이 결과는
설치된 앱의 갱신, 숨겨진 정적 코드 전체의 부재, 실제 창·GPU 또는 Windows 실행을
증명하지 않는다. Direct3D 소스의 교차 컴파일과 장면 검사는
[iiGUI 장면 문서](../../../SDK/iiGUI/docs/SubtreeScenes.md)에 기록한다.

`Congregation.tool_settings`는 값 보존·로그 변환·증감·범위·설정 왕복·엔진 연결·시간 경계를 검사한다. `Congregation.editor_layout`은 캔버스 맞춤과 좌표를 검사한다. `Congregation.native_window_contract`와 `Congregation.native_window_colors_vulkan`은 기준 크기·최소 크기에서 사이드바가 없고 세로 도구 막대가 왼쪽 끝에 있는지, 도구 선택이 작동하는지, 캔버스와 타임라인이 빈 공간 없이 확장되는지 검사한다. `Congregation.figma_ui_native`와 `Congregation.figma_ui_vulkan`은 변경된 실제 창의 조작과 캡처를 검사한다. 기존 네이티브 편집 회귀 검사와 macOS 번들 재배치 검사를 함께 수행한다.

실제 수행 결과와 화면은 FIGMA_UI_VERIFICATION.md에 기록한다. macOS의 결과로 Windows·Linux의 실행 성공을 주장하지 않는다.

## Color·Metric 전환

현재 화면은 [LVUI 공통 스타일](UI_STYLE_TOKENS.md)을 따른다. 제품별 배치 치수만 별도로 보존하며 색상은 LVUI 뷰와 네이티브 C++에서 같은 공유 토큰을 참조한다.

## 환경설정 프로필의 콘텐츠 기준 크기

Figma [Profile](https://www.figma.com/design/r4E0PNUdZuo6dEiMEitF2I/Congregation?node-id=268-2664)은
시작점 정렬이며 공통 Large Avatar의 자연 크기는 64×64이다. 프로필 입력 리스너는
공통 Avatar 자식의 크기를 따르고, 이름 입력은 원본처럼 432×22를 유지한다.
프로필 사진 선택·삭제와 입력 영역의 클릭 전달은 기존 동작을 유지한다. 실제
위젯 트리를 사용한 창 없는 검사에서 리스너의 64×64 크기와 영역 밖 클릭의 무시,
사진 선택·삭제, 이름 입력 크기 및 프로필 메뉴 열기를 확인했다.
