# 웹 계정과 라이선스 확인

데스크톱 앱은 작업 공간을 연 뒤 SocietyDaemon의 로컬 서명 허가를 백그라운드에서 확인한다.
첫 확인 중에는 로컬 편집이 가능하지만 검증된 허가로 간주하지 않으며, 확인된 허가가
필요한 공유와 업데이트는 대기한다. 미보유 또는 확인 불가 결과가 도착하면 작업을
보존한 채 계정·라이선스 안내와 재시도를 표시한다. 유효한 허가를 받은 현재
실행은 이후 데몬 중단이나 토큰 만료 때문에 잠기지 않는다. 다음 실행에서는 다시
제품·기기·서명을 검사하며, Society 창이 열려 있을 필요는 없다.
기본 소켓에 데몬이 없으면 macOS·Linux에서 설치된 라이선스 전용 데몬을 창 없이
기동한다. `SOCIETY_DAEMON_EXECUTABLE`로 절대 실행 경로를 지정할 수도 있다.
기동 성공은 허가가 아니며 서명과 현재 계정을 별도로 확인한다.

Society가 iisacc 계정과 웹 라이선스 확인을 소유한다. Congregation은
`iiAccountManager::SocietySession`의 같은 사용자 로컬 채널을 통해 제품·기기별
서명 결과를 받고 서명과 만료를 독립 검증한다. 데스크톱 앱은 비밀번호, 서버 쿠키나 Bearer를
받지 않는다. 서버의 무료 정책에 따른 Congregation 허가는 구매 기록을 만들지 않는다.
Society 연결 실패, 위조 응답과 미보유 응답은 허가하지 않는다. 업데이트 확인과 승인도
Society 로컬 브로커를 거친다. 로그인과 로그아웃은 Society에서 관리한다.

`Congregation.services`는 로컬 서명 허가·거부·다른 기기의 토큰, 첫 허가 이후
실행 중 유지와 로컬 업데이트 요청을 검사한다. 로컬 채널은 현재 macOS와 Linux에 구현되어 있으며
Windows는 별도 구현이 필요하다. 과거의 제품별 웹 세션은 데스크톱 경로에서 읽지
않지만 보안 저장소에서 자동 삭제하지는 않는다. 설치본과 실제 계정의 동작은 별도 검증이다.

## iPad의 웹 계정 확인

iPad에 Society가 없는 동안에는 제품 범위로 제한된 iiAccountManager 웹 세션을
사용한다. 사용자가 시스템 브라우저에서 기기 연결을 승인하면 앱은 해당 세션으로
서버의 Congregation 라이선스 보유 여부를 백그라운드에서 확인한다. 첫 확인 중에는
로컬 편집을 임시로 허용하며, 결과의 제품과 계정이 현재 세션에 일치하고 보유 상태가
명시적으로 참인 경우 작업 공간을 유지한다. 로그인만으로 검증된 허가를 부여하지
않으며, 연결 오류·잘못된 응답·미보유는 안내 화면과 재시도로 처리한다. 세션은 플랫폼 보안
저장소에 보관하며 다음 실행 시 서버 확인을 다시 수행한다. 데스크톱의 Society
로컬 허가 경로는 그대로 유지한다.

과거 직접 웹 로그인 경로인 2026-10-30 Mac의 1.0.2 빌드에서 실제 계정으로 새 브라우저 연결을 승인하고 편집기와
온라인 라이선스 검증 완료 상태를 확인했다. 앱 재시작 후 저장 세션의 자동 복구,
인증된 업데이트 확인의 당시 빈 카탈로그 응답과 Quit 후 프로세스 종료도 확인했다.
이후 1.0.2가 운영 카탈로그에 등록됐다.
이는 업데이트 패키지 설치나 다른 플랫폼까지 검증했다는 뜻은 아니다.

로컬 개발 빌드는 `CONGREGATION_ACCOUNT_MANAGER_PREFIX`,
`CONGREGATION_UPDATE_MANAGER_PREFIX`, `CONGREGATION_SHARED_CANVAS_PREFIX`,
`CONGREGATION_FILE_PROVIDER_PREFIX`로 사용할 SDK 패키지를 지정할 수 있다. macOS 번들은
실제 링크된 의존성을 우선하며 지정된 패키지 디렉터리 밖의 심볼릭 링크를 거부한다.
특히 같은 이름의 이전 iiPaintEngine 라이브러리가 다른 SDK 디렉터리에 있더라도
CMake가 링크한 정확한 라이브러리를 먼저 선택한다. iiFileProvider와 iiSDKCore도
실제 링크 대상의 파일명과 Mach-O 설치 이름을 함께 확인하여 버전 별칭이 가리키는
이전 라이브러리가 번들에 섞이지 않도록 한다.
