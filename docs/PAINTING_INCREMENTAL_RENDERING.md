# 필기 입력과 부분 캔버스 합성

## 계약

- 브러시와 지우개는 입력 표본의 좌표, 시간, 압력과 방향을 빠짐없이 순서대로 편집 엔진에 전달한다.
- LVUI `NativeView` 등 중첩 위젯을 거친 입력도 캔버스 자신의 좌표계로 변환한다. 누름부터 이동과 놓기까지 실제 입력 경로를 통해 전달하고, 중간 픽셀과 확정된 획을 검증한다.
- 입력이 짧은 시간에 연속되거나 처리 중 재진입해도 애플리케이션이 종료되지 않아야 한다. 입력 대기 한도를 넘으면 진행 중인 획을 안전하게 취소하고 이후 입력을 다시 받을 수 있어야 한다.
- 실시간 미리보기는 실제로 변경된 픽셀을 문서 좌표로 변환하여 겹치는 가시 타일만 무효화한다. 화면 프레임 전의 여러 입력은 하나의 합성 요청으로 모은다.
- 긴 펜 획은 각 입력을 순서대로 픽셀에 반영해야 하며, 펜을 놓은 뒤에도 시작·중간·끝이 모두 남아야 한다. 테이퍼를 사용하는 경우에도 필압과 형상을 보존하고, 표시 결과와 확정 결과, Undo/Redo 및 저장 후 다시 연 결과가 일치해야 한다.
- 표시 단계에서도 타일을 독립적인 보유 레이어로 전달하여 한 타일의 변경으로 다른 타일의 전경 이미지 전체를 다시 래스터화하지 않는다. 운영체제의 최종 화면 프레임 표시는 별도의 과정이다.
- 레이어 변환, 선택 마스크, 프레임 전환, 취소, 에어브러시 및 Undo/Redo의 정확성을 유지한다. 테이퍼의 길이 기준은 아래의 고정 거리 계약을 따른다. 비지역 효과 등 안전한 부분 무효화를 보장할 수 없을 때는 보수적인 전체 무효화를 허용한다.
- 화면 프레임 스케줄러가 없는 환경에서는 동기식 표시로 폴백하며, 예약된 콜백은 뷰 수명을 넘어 접근하지 않는다.

## 검증

입력 묶음 전후 타일 생성 수와 픽셀 결과를 검사하고, 여러 타일을 가로지르는 획, 선택 마스크와 변형 레이어, 취소, 테이퍼, 에어브러시 및 실행 취소·재실행을 회귀 검증한다. 빌드와 테스트 결과를 실행 기기 성능 측정과 구분한다.

## 구현 경계

iiGUI 입력 디스패처가 제공하는 `local_position`은 이벤트를 받은 캔버스 위젯을 원점으로 하는 좌표이다. 중첩 콘텐츠에서 이벤트의 `x`, `y`는 콘텐츠 범위의 좌표이지만 위젯 스냅샷의 경계는 창 기준이므로 이 둘을 빼면 획이 어긋날 수 있다. `CanvasView::localize_input`은 디스패처가 제공한 위젯 좌표를 우선하고, 이를 갖지 않는 직접 주입 입력에만 창 기준 경계로 변환한다. 드롭 입력도 동일한 변환을 사용한다.

`Artwork`는 iiSharedCanvas 비트맵 편집기의 변경 픽셀 경계를 입력마다 수거한다. 현재 표시에 필요한 변경 영역과 전체 획의 누적 영역을 별도로 보관하므로 선택 마스크의 이전 미리보기와 청크 획의 커밋 범위를 유지한다. 편집기 좌표는 획 시작 시 확정한 레이어 변환으로 문서 좌표에 투영하고, 보간에 필요한 인접 픽셀을 포함한다.

`CanvasView`는 해당 영역과 겹치는 현재 프레임의 캐시 타일만 제거한다. iiGUI 위젯의 프레임 요청은 여러 입력을 한 번의 표시 갱신으로 묶는다. 선택 마스크 미리보기도 다시 합성할 가시 타일과 그 보간 여유에 필요한 부분만 계산한다. 프레임 소스가 없으면 같은 변경 영역을 즉시 합성한다. 레이어 필터처럼 영향 범위가 국소적이라고 보장할 수 없는 경우에는 전체 캐시와 미리보기를 사용한다.

캔버스의 내부 콘텐츠 호스트는 가시 타일마다 별도의 보유 표시 레이어를 유지한다. 변화가 없는 타일에는 기존 이미지와 레이어를 그대로 사용하고 선택 경계 등의 장식은 별도 레이어에 둔다. 호스트는 포인터 입력을 캔버스에 전달한다. 확대나 창 크기 변경으로 필요한 타일 수가 늘면 레이어 묶음을 다시 구성한다. 이 방식은 iiGUI의 전경 래스터화가 변경 타일 이외의 이미지를 포함하지 않게 하며, 네이티브 렌더러가 최종 화면 프레임을 표시하는 동작은 유지한다. 독립 레이어용 호스트가 없는 임베딩 환경은 기존 단일 표시 경로를 사용한다.

다른 UI를 위한 레이어 여유를 남기도록 캔버스의 레이어 예산을 iiGUI 전체 상한의 절반으로 제한한다. 초대형 뷰에서 가시 타일이 예산을 넘으면 가까운 순서의 타일을 한 레이어에 묶으므로 해당 묶음은 함께 래스터화된다. 캐시는 일반 상한을 넘더라도 현재 보이는 타일을 제거하지 않고 화면 밖의 타일부터 정리한다.

이 변경은 일반 브러시·지우개와 그 에어브러시 입력 경로에 적용된다. Quick Mask는 별도의 화면 크기 마스크 미리보기를 생성하며 Clone Stamp는 별도의 전체 캐시 갱신 경로를 사용한다. 두 특수 미리보기에는 위의 부분 합성 보장이 적용되지 않는다.

획 확정 중 문서 변경 알림은 별도의 전체 캔버스 갱신을 일으키지 않는다. 선택 합성과 취소는 필요한 획 영역을 무효화한다. Undo/Redo 및 독립적인 문서 변경은 기존의 전체 새로 고침 경로를 유지한다.

입력 종료 이벤트가 누락되어 다음 획이 시작되면 진행 중이던 획을 취소한다. 이전 획의 변형 정보를 버리기 전에 그 변경 영역을 복원 대상으로 예약하고, 새 획의 변경 영역과 같은 프레임에 함께 표시한다.

`Congregation.painting_damage_integration`은 실제 펜 입력 경로와 프레임 루프를 헤드리스 위젯에 연결한다. 이 검사는 링크한 iiGUI 라이브러리와 일치하는 내부 테스트 헤더 오버레이를 `CONGREGATION_IIGUI_TEST_HEADERS`로 제공한 구성에서 활성화된다. 타일의 RGBA 데이터를 전체 참조 합성과 비교하므로 생성 횟수만 확인하는 검사가 아니다.

`Congregation.native_canvas_stroke_integration`은 LVUI 메인 화면과 중첩 콘텐츠 호스트를 통과하는 마우스·펜·터치 입력을 검증한다. 흰 배경을 가진 새 캔버스와 투명 캔버스에서 시작점과 이동 중간의 문서 픽셀, 프레임 루프가 표시한 RGBA 픽셀, 획 확정, 실행 취소·재실행 및 캔버스 밖의 입력 캡처를 검사한다. 마우스 표본 256개와 기본 브러시·테이퍼 표본 96개를 연속 전달하고 그동안 생성된 네이티브 장면의 유효성을 확인한다. 입력 처리 중 300개를 재진입시키는 경우에는 진행 중인 획의 안전한 취소와 다음 획의 복구를 검사한다. 브러시 크기 증가·감소 버튼을 각각 32회 연속 입력하고, 도구·색상·레이어 컨텍스트 메뉴와 색상 팝업이 중첩 콘텐츠에서 열리는지도 확인한다. 테스트용 호스트를 창 원점에서 떨어뜨려 좌표계 혼용을 탐지한다. 자동 테스트는 합성 입력이며 실제 앱·GPU·물리 장치의 실행 결과를 뜻하지 않는다.

## 필압 불투명도

브러시의 기본 Opacity는 전체 획의 불투명도 상한이다. Dynamics의 Minimum opacity와 Maximum opacity는 필압 0과 1에 대응하는 배율이며, 두 값 사이를 선형 보간한다. 기본 범위는 0–100%이다. 최소값을 최대값보다 높이면 최대값도 함께 올리고, 최대값을 최소값보다 낮추면 최소값도 함께 낮춘다. 마우스는 필압 1로 처리한다. 붓의 이동 속도와 가속도는 이 불투명도 배율에 영향을 주지 않는다. 크기·유량의 필압 반응과 캔버스의 색상, 선택 마스크 및 합성은 별도의 설정이다.

기존 도구 설정의 `velocity` 항목은 호환성을 위해 읽고 폐기하며, 새 범위의 기본값 0–100%를 적용한다. 새로운 설정은 `minimum-opacity`와 `maximum-opacity`를 저장한다. 손상되거나 역전된 저장 범위는 기존 설정을 변경하지 않고 거부한다. 범위, 속도 독립성, 저장·복원 및 기존 설정 이행은 `Congregation.tool_settings`에서 검증한다.

## 도구 패널 이행: 포즈와 일부 동역학

Figma Tool 패널 이행 중인 부분 구현이다. Brush Pose의 Tilt X/Y, Rotation, Pressure와 각 Override를 `BrushDynamics::pose`로 전달하며 선택한 채널만 입력을 대체한다. 산포의 Both Axes, Count, Count Jitter와 제어 입력은 기존 `BrushScatter`에 연결한다. Noise의 활성화와 Amount, Wet Edges의 활성화와 Edge Strength는 기존 래스터라이저 효과에 연결한다. Shape Dynamics의 Size·Angle·Roundness Jitter, 제어 입력, 최소 직경·원형도, Flip X/Y Jitter와 Brush Projection 및 Color Dynamics의 Hue·Saturation·Brightness Jitter, Purity, Apply Per Tip은 기존 엔진 옵션에 연결한다. 이전 버전 도구 설정에서 새 항목이 빠져 있어도 안전한 기본값으로 복원한다.

이 항목들의 UI는 기존 도구 패널에 추가한 중간 단계이며 Figma 전체의 배치와 동일하지 않다. Figma에 있는 텍스처 선택, 텍스처·색상·전송 지터의 Control 선택, 필압 곡선 및 나머지 Shape·Scattering·Color·Transfer 설정과 Noise 입자 크기, Wet Edges 폭·확산, Build-up 설정은 이 변경에서 완성되지 않았다. 일부는 엔진에 기반이 있지만 앱에 연결되지 않았고 일부는 엔진 자체의 추가 구현과 검증이 필요하다. 테스트 결과와 실제 펜·장치 검증은 별도로 기록한다.

형상과 산포의 제어 입력은 현재 선택 상자를 클릭할 때 순서대로 전환한다. Figma의 펼침 선택 메뉴 동작은 아직 이행되지 않았다.

## 도구 패널 간격

도구 패널은 LVUI 간격 토큰 `space16`으로 섹션을 분리하고, 같은 섹션의 파라미터 내부 여백은 `space2`로 유지한다. Brush 팝오버의 항목과 필압 곡선 설명에는 `space4`를 사용한다. 확장 패널의 콘텐츠 높이는 실제 섹션 수에 따른 구분 간격을 포함한다. 도구 패널의 상호작용과 설정값은 간격 변경으로 바뀌지 않는다.
## 실시간 브러시 획 입력

입력은 필압과 순서를 유지해 브러시 엔진으로 즉시 전달하고, 새 표본이 바꾼
타일만 문서 미리보기에 반영한다. 일반 단일 프레임 래스터 획과 내부 이력이
필요한 청크 문서는 입력 중 타일 합성을 사용하고, 놓을 때 조건에 따라 변경
타일로 하나의 Undo 항목을 만든다. 단일 자산의 선택·테이퍼 획도 타일 단위로
확정한다. 공유 프레임처럼 별도의 구조 변경이 필요하거나 이력 예산이 너무
작은 경우는 기존 문서 스냅샷 이력을 사용한다. 취소하면 원래 문서로 돌아간다.

테이퍼의 Start와 End는 최종 획 길이가 아니라 브러시 지름에 대한 백분율이다.
따라서 이전 획 전체를 보관하거나 놓을 때 재생하지 않는다. 시작 부분을 지난
자국은 즉시 누적하고, 현재 끝에서 설정된 거리 안의 자국만 잠정 합성한다.
다음 입력은 그 짧은 끝부분을 교체하며 이미 지난 부분은 그대로 둔다. 스무딩의
끝 따라잡기도 같은 임시 합성에 포함해 놓을 때 이미 보인 픽셀이 변하지 않게 한다.
정지한 에어브러시처럼 끝부분 자국이 16,384개 또는 브러시 크기로 추정한 투영
픽셀 1,048,576개의 한도를 넘으면 가장 오래된 자국을 그 시점에 보이는 크기로
고정해 메모리를 제한한다. 실제 새 종료 위치가 입력된 경우
그 새 입력으로 인한 변화는 반영한다.
이 계약은 현재 지원하는 유한 캔버스에 적용된다. 예전 비한정 문서의 자동 확장
입력은 호환성 경로로만 유지되며 고정 거리 끝 테이퍼를 제공하지 않는다.

저장이나 이력 한도를 넘는 등 확정에 실패한 경우 이전 문서와 Undo/Redo 스택을
보존하고 오류를 표시하며, 이전 미리보기가 남지 않도록 획 영역을 무효화한다.
내구성 저장은 동기식이므로 저장장치 대기 시간은 획 종료에 남는다.

회귀 시험은 필압이 변하는 12초 획의 시작·중간·끝과 저장 재개방, Undo/Redo를
확인한다. 기본 테이퍼와 256px 브러시의 긴 반복 획 및 촘촘한 1px 브러시로 기존
투영량과 자국 개수의 누적 한도를 각각 넘기고,
iiGUI 시험용 내부 헤더를 지정한 경우 초기 맞춤 확대율과 관계없이 배율을 1:1로
지정해 프레임 루프의 여러 표시 타일과 저장 실패 후의 전체 화면 복구도 검사한다.
이는 합성 입력에 대한 호스트 시험이며 실제 iPad의
화면이나 펜으로 확인했다는 뜻은 아니다.

`StrokeStreamingIntegration`은 고정 거리 양끝 테이퍼, 종료 전후 픽셀 비교,
필압과 스무딩, 페더 선택, 지우개, 저장·재개방 및 Undo/Redo를 확인한다.
`LongStrokePresentation`은 여러 표시 타일의 전체 픽셀을 놓기 전후로 비교한다.

## 성능 측정 계약

`CONGREGATION_PAINT_PROFILE=1`로 새 프로세스를 실행하면 완료된 각 붓 획의
시작, 이동 표본 처리, 획 진행 중 CPU 표시 구성 및 확정 시간을 표준 오류에
`CONGREGATION_PAINT_PROFILE` 한 줄로 출력한다. 이동과 표시의 P50/P95/P99는
2의 거듭제곱 마이크로초 구간의 상한이며 최댓값은 실제 관측값이다. 입력
시각 간 최대 간격은 표본 간격이지 펜 접촉부터 화면 표시까지의 지연이 아니다.
프레임 제출·GPU 완료·화면의 빛이 바뀌는 시각은 포함하지 않는다. 계측은
명시적으로 켠 경우에만 동작하며 포인터 좌표, 문서 내용과 필압 값은 기록하지
않는다. 취소한 획은 보고하지 않는다.

헤드리스 부하 검사는 같은 문서에서 전체 직렬화, 획 시작, 이동 입력, 512픽셀과
256픽셀 표시 영역의 CPU 합성, 획 종료를 각각 계측한다. 작은 영역의 픽셀은
큰 영역의 대응 픽셀과 비교한다. 작은 붓과 큰 붓을 구분하고,
필압을 포함한 입력과 중간 픽셀, Undo/Redo 결과를 함께 확인한다. 출력의 시간은
해당 구간의 벽시계 시간이며 합성 입력과 호스트의 파일 저장 비용을 포함한다.
이를 iPad의 펜 접촉부터 실제 화면 표시까지의 지연이나 GPU 처리 시간으로
해석하지 않는다. 재현 실행은 `Congregation.stroke_performance` 검사로 수행한다.
macOS 검사 프로세스는 `DYLD_*` 라이브러리 검색 경로를 제거해 CMake에서
선택한 iiPaintEngine이 다른 설치본으로 대체되지 않도록 한다. 할당량은 측정
스레드에서 일반 C++ `new`로 요청한 바이트의 합이며 최대 상주 메모리가 아니다.
`--extended`는 4K와 8K 합성 부하를 추가한다.
`Congregation.stroke_history_4k`와 `Congregation.stroke_history_variants_4k`는
4K 일반 획과 선택·테이퍼 획의 확정 및 Undo/Redo 할당량을 별도로 회귀 검사한다.

단일 프레임에서 공유되지 않는 래스터 레이어에 그리는 획은 선택 영역이나
테이퍼 적용 여부와 관계없이 이력 예산이 64×64 타일 한 장의 전후 픽셀을 담을
수 있는 경우 변경 타일의 전후 픽셀을 이력으로 보유한다. 이때 전체 문서가
이력 예산보다 커도 변경 타일이 예산 안에 들면 한 획을 허용한다. 이력 예산이
그보다 작으면 기존 문서 스냅샷 경로를 사용한다.
취소와 변경 없는 획은 기존 Redo를 보존하고, 저장이나 이력 예산이 실패하면
확정 전 문서와 이력으로 되돌린다. 이력에는 변경 전후의 저작 정보와 문서
형식 버전도 보관해 Undo/Redo가 전체 문서 스냅샷과 동일한 메타데이터를
복원한다. 공유 프레임 등 별도 구조 변경이 필요한 획은 기존 문서 스냅샷
경로를 유지한다. 저장 트랜잭션은 동기로 완료하므로 저장장치 동기화 대기는
여전히 획 종료와 Undo/Redo의 지연에 포함된다.

## 완료된 비트맵 이력의 부분 저장 계약

일반 유한 래스터 획의 확정과 Undo/Redo는 문서 전체를 복사하지 않고 완성된
이력 항목의 변경 픽셀과 저작 정보·문서 버전만 파일에 반영한다. 작업은 기존
Undo/Redo 스택의 항목 하나로 유지한다. 파일의 이전 픽셀·리비전·메타데이터가
예상과 다르거나 쓰기에 실패하면 문서와 양쪽 스택은 기존 상태를 보존한다.
선택 마스크와 테이퍼가 적용된 단일 자산 획도 변경된 타일만 비교하고,
마스크 합성과 테이퍼 결과를 동일한 단일 타일 이력으로 확정한다. 선택 바깥의
픽셀과 변경 없는 획의 Redo 이력은 그대로 유지한다. 공유 프레임의 복사처럼
문서 구조가 바뀌는 경우는 별도의 구조 이력 경로를 사용한다.
부분 선택률이 있는 페더 마스크가 타일 경계를 지나는 결과는 전체 이미지 기준
합성과 픽셀별로 비교한다.
구조를 바꾸지 않는 일반 유한 청크 획도 문서 전체가 이력 예산 안에 들어가는지와
무관하게 변경 타일 이력을 사용하며, 확정·Undo·Redo에 전체 문서를 복사하지 않는다.
동일한 유한 청크 자산의 선택·테이퍼 획도 실제로 손상된 타일을 수집해
합성하고 이력을 만든다. 변형된 청크 자산은 조건에 따라 기존 스냅샷 경로가
남아 있으며, 저장 실패를 복구하는 예외 경로에도 전체 문서 복사가 남아 있다.
여러 입력으로 이어진 긴 대각선에서 둘러싼 영역보다 손상 타일이 적을 때도
타일 수에 맞춰 예산을 계산하고 이력을 복원하는지 검사한다.
macOS 번들에는 CMake가 선택한 iiSharedCanvas 네이티브 라이브러리를 명시적으로
전달해 오래된 통합 SDK 복사본보다 우선하며, 해당 스테이징 디렉터리만 추가로 허용한다.
공유 라이브러리만 번들에 복사하고 정적 라이브러리는 실행 파일에 링크한다.
iPadOS에서는 iiSharedCanvas 네이티브 패키지가 정적 라이브러리여야 하며 동적
프레임워크는 CMake 구성 시 거부한다. 정적·동적 대상의 허용 여부를 각각 시험한다.
작은 획에 대한 4K·8K 확정·Undo·Redo의 C++ 할당 요청 합을 각각 32MiB 미만으로
검사한다. 저장 트랜잭션은 내구성 성공을 확인할 때까지 동기식으로 유지한다.

작업 파일을 다른 연결이 잠시 읽는 동안에는 iiSharedCanvas의 Native 파일 쓰기가
SQLite 잠금 해제를 각 요청마다 최대 250ms 기다린다. 기다리는 동안에도 원래
이력은 유지하며, 잠금이 계속되거나 외부 수정이 감지되면 작업을 거부하고 픽셀과
Undo/Redo 스택을 원상태로 남긴다. 이 제한은 디스크 동기화 시간이나 화면 표시
지연의 상한이 아니다. `InteractiveRasterHistory`는 읽기 경합 중의 Undo/Redo와
지속적인 쓰기 잠금 시 실패 복구 및 저장된 픽셀의 일치를 검사한다.

색상 모델의 변경은 캔버스의 현재 색과 그라디언트 기본색에 반영하며,
색과 무관한 필압 곡선을 다시 그리지 않는다. 현재 LVUI 화면에는
`brush-preview` 위젯이 없으므로 없는 위젯을 찾기 위해 매번 전체 트리
스냅샷을 생성하지 않는다. 필압 설정이 바뀔 때는 기존 곡선 갱신 경로를
유지한다. 색상 변경과 곡선의 표시 유지 여부를 메인 창 검사에서 확인한다.
