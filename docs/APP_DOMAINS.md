# 앱 소스 도메인 구조

`App/`은 플랫폼 계층과 엔진 계층으로 나누지 않고 기능의 변경 이유에 따라 구분한다. 각 도메인의 C++ 헤더는 구현과 같은 디렉터리에 두고, 해당 도메인의 LVUI 화면도 그 도메인에 둔다.

| 영역 | 책임 |
| --- | --- |
| `Application` | 앱 생명주기, 최상위 창과 메뉴 |
| `Workspace` | 편집 작업 공간과 화면 상태 조정 |
| `Canvas`, `Document` | 캔버스 표시·생성·그리기와 문서 모델·명령·형식 |
| `Tools`, `Timeline`, `Color` | 도구 설정, 타임라인, 색상 모델과 해당 화면 |
| `Assets`, `Storage` | 에셋 라이브러리와 Society 저장소 연결 |
| `Account`, `Agent`, `Collaboration`, `Preferences`, `Update` | 계정, 에이전트, 협업, 환경설정, 업데이트 |
| `Shared` | 여러 도메인이 쓰는 공통 화면·유틸리티 계약 |

도메인 간 포함은 `Canvas/Artwork.h`처럼 `App/`을 기준으로 명시한다. 같은 디렉터리의 헤더는 기존처럼 파일 이름으로 포함할 수 있다. 새 도메인을 추가할 때 범용 디렉터리로 우회하지 말고 대상 기능의 소유권과 의존 방향을 먼저 정한다. 같은 개념과 상태는 해당 도메인에 한 번만 정의하고 다른 도메인은 그 소유자의 계약을 사용한다. 한 객체가 여러 도메인을 담당하지 않으며 각 모듈에는 하나의 명시적인 역할만 부여한다. 이 이동은 기존 기능이나 플랫폼 지원 범위를 바꾸지 않는다.

구조 회귀 검사는 도메인 소유 파일, 선언형 뷰, 이전 두 디렉터리와 오래된 경로 참조를 확인한다. 빌드 및 기능 테스트는 별도로 실행하며, 자동 검사는 운영체제에서 앱을 열거나 실기기를 조작한 결과를 뜻하지 않는다.

문서 레이어의 변경 값과 필드 적용 의미는 iiSharedCanvas가 소유한다. 앱 이력은 문서 변경과 앱의 선택 상태가 발생한 순서를 조정하며 SDK의 레이어 필드 모델을 중복 정의하지 않는다. 이 계약은 전체 `Artwork` 분리가 완료되었다는 뜻은 아니다.

현재 `Artwork`는 브러시 입력, 선택 상태, 작업 파일과 이력 조정까지 담당하고 파일 소유 문서와 별도의 `draft_`도 유지한다. 따라서 단일 도메인 소유 원칙은 이 객체 전체에 아직 충족되지 않으며, 나머지 책임 분리와 문서 중복 제거는 후속 이행 대상이다.

앱 생명주기 객체는 실제 편집에 연결되지 않은 별도의 캔버스 설정 객체를 소유하지 않는다. 색상 값은 색상 도메인이 정의하며 팔레트와 독립 쿼리 모델이 이를 참조한다.
