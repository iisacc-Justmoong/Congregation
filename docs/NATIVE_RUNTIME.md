# Qt 없는 Congregation 실행 구조

## 시작 캔버스 크기

앱이 새 시작 캔버스를 만들 때는 창이 실제로 표시되는 디스플레이의 현재 픽셀
해상도와 방향을 사용한다. 작업 가능 영역이나 창 크기로 대체하지 않으며 가로·세로
비율도 그대로 유지한다. 기존 문서 복구 또는 명시적 파일 열기에 성공했다면 해당
문서의 크기를 유지한다. 디스플레이가 아직 결정되지 않은 경우에는 값이 준비될 때까지
대기하고, 값을 확인할 수 없거나 문서 크기 제한을 넘으면 잘못된 크기의 캔버스를
만드는 대신 오류를 표시한다. 새 캔버스의 Society Files 저장 계약은 유지한다.
출력 정보가 늦게 도착하는 경우 최대 5초 동안 확인하며, 기다리는 동안 사용자가
기존 문서를 열거나 협업 문서를 받으면 그 문서를 새 시작 캔버스로 교체하지 않는다.

## Society 새 캔버스 저장 계약

새 캔버스의 작업 파일은 선택된 Society 저장소의 `Files` 안에 고유 이름으로 만든다.
첫 저장과 다른 이름으로 저장은 사용자가 `Files` 아래의 경로를 명시적으로 선택해야
하며, 임시 작업 파일을 정식 저장 경로로 오인하지 않는다. 기존 파일·다른 저장소·
리디렉션된 경로를 임시 파일로 취급하거나 자동 삭제하지 않는다. 데스크톱에서
저장소를 확인할 수 없으면 새 캔버스 생성을 실패로 보고한다. 모바일에서 Society
시스템 저장소가 없으면 iiSocietyContainer가 앱 샌드박스에 별도의
`Society.societycontainer`를 만들고 그 안의 `Files`를 사용한다. 이 앱별 컨테이너는
OS의 Society 드라이브로 등록하거나 다른 앱과 공유하지 않는다.

새 캔버스를 닫거나 교체할 때는 기본 배경과 초기 문서 구조 이외의 작업 내용이
정말 없는 경우에만 소유한 임시 파일을 삭제한다. 내용·문서 구조·파일 소유권이나
저장소 식별을 확실히 확인할 수 없다면 보존한다. 명시 저장된 파일과 내용이 있는
미저장 파일은 보존하고, 저장·생성 실패는 기존 문서와 파일을 유지한다. 비정상 종료
뒤에 소유권을 증명할 수 없는 파일을 자동 삭제하지 않는다.
초기 상태 비교는 생성과 정리 시에 수행하며 펜 입력이나 매 획마다 문서 전체를
복사하거나 검사하지 않는다.

첫 저장에는 운영체제 저장 대화상자를 사용하고 `Files` 하위의 `.iisc` 경로만
허용한다. 명시 저장 뒤에는 작업 파일과 저장 파일의 내용 및 식별자가 일치하고 그
뒤에 수정되지 않은 경우에만 작업 파일을 정리한다. 그림을 그리거나 문서를 수정한
뒤 저장하지 않았다면 작업 파일은 `Files`에 남는다. 데스크톱에서 저장소가 연결되지
않았거나 모바일에서 앱별 저장소도 준비하지 못한 경우에는 안내용 빈 화면을 표시하고
편집을 막으며, 새 캔버스 또는 파일 열기는 다시 시도할 수 있다. 저장소 선택 파일과
실제 컨테이너가 다른 경우에도 작업 파일을 보존한다.

데스크톱의 선택된 Society 저장소와 모바일 앱별 저장소를 인식한다. iPad에서 서명된
Society App Group에 유효한 시스템 저장소가 나타나면 시작 시 백그라운드 작업으로
앱별 컨테이너의 내용을 복사한다. 충돌 파일은 이름을 구분하고 원본은 보존하며,
진행 중인 데이터베이스나 리디렉션이 확인되면 이관을 미루고 앱별 저장소를 유지한다.
공용 저장소 접근은 App Group 서명과 해당 기기의 Society 준비 상태에 좌우된다.
iPad의 명시적 파일명 저장 대화상자는 아직 제공하지 않는다. Android 앱별 저장소는
같은 API로 만들 수 있지만 Society의 ContentProvider를 통한 자동 이관은 아직 연결하지
않았다. Society가 없는 기기에서 만들어 보존한 작업 파일은 최근 문서에 자동 등록되지
않으며, 공용 저장소 이관 대상에는 포함된다.

실행 소스와 LVUI 뷰는 기능별 `App/` 도메인에 있다. 앱 진입점·이벤트 루프·작업 수명은 iiSDKCore가 소유하고 iiGUI Host가 운영체제 창에 연결한다. `.lvui` 뷰는 `Window`, `HStack`, `VStack`과 컨트롤을 중첩해 직접 선언하고 빌드 시 C++23으로 생성한다. 상태와 이벤트는 import한 C++ 뷰모델에 연결한다. HTML 태그와 CSS형 인라인 스타일을 사용하지 않으며 LVRS, 브라우저·WebView·Qt·QML 엔진을 링크하지 않는다.

`EditorBackend`의 목록은 독립 LVUI `ListSource`와 반응형 리비전을 제공한다.
공유 색상도 관찰 가능한 값과 명령으로 노출한다. 제품 상태에서 생성한 행은
LVUI 목록 원본으로 전달된다. 뷰모델과 현재 화면의 구현 범위는
[LVUI 뷰모델 계약](LVUI_VIEWMODELS.md)을 따른다.

`Artwork`는 제품의 도구·실행 취소 정책이다. 문서, 픽셀, 벡터, 변환, 타일 합성과 파일 편집은 iiSharedCanvas Native에 위임한다. 파일과 SQLite는 iiFileProvider가 소유한다. 펜 입력은 한 스트로크당 한 문서 커밋이며 취소하면 미리보기 픽셀을 되돌린다. 확대·이동·선택·프로필·브러시 설정은 저장 문서의 리비전을 바꾸지 않는다. 실행 취소는 최대 32개 명령, 타일·부분 변경과 남아 있는 직렬화 스냅샷을 합쳐 64 MiB로 제한한다.

제품은 유한 캔버스를 사용한다. iPad의 손가락 입력은 운영체제가 표본을 전달하고
iiSDKCore와 iiGUI가 이동·핀치 제스처를 해석한다. 캔버스는 전달된 내용 이동량을
사용하며 포인터 취소 시 진행 중인 획을 되돌린다. 손을 뗀 뒤의 관성과 중단·감속은
앱별 계산 없이 iiSDK의 입력 및 프레임 시계가 처리한다. 휠 입력은 기존 동작을 유지한다.
iPad의 콘텐츠는 iiGUI 창의 전체 영역을 사용해 상단과 하단 시스템 표시 영역 아래까지
확장된다. 분할 화면에서는 실제 장면 창의 크기를 따른다.
화면은 보이는 영역만 최대 512픽셀 타일로 전달한다. 레이어 추가·삭제·복제·이름·가시성·순서와 벡터 도형, 텍스트 배치, 이미지 가져오기를 제공한다. 선택 도구에서 드래그는 이동, Shift 드래그는 배율, Alt 드래그는 회전이다. Space 또는 가운데 버튼은 화면 이동이며 Control/Meta+Space 드래그는 임시 확대이다. 텍스트 입력에 포커스가 있으면 캔버스 단축키와 메뉴 실행 취소를 억제한다.

저장은 이식 가능한 `.iisc`이며 작업 복구본은 별도 SQLite 문서이다. 최근 복구 설정은 앱의 관리 디렉터리에 있는 정규 UUID 이름의 일반 파일만 허용한다. 이전 `.vrc`는 내부 IISC, 내장 PNG, 래스터 레이어 및 도형을 읽고 개별 네이티브 레이어로 이행한다. 이전 텍스트는 네이티브 글꼴로 그린 비트맵 레이어가 된다. 알 수 없는 개체·누락된 픽셀·지원하지 않는 합성은 거부하며 원본을 덮어쓰지 않는다.

열기에서는 파일의 짧은 서명으로 네이티브 IISC·SQLite 문서를 식별한다. 네이티브 읽기에 실패하면 그 오류를 전달하고 이미지 가져오기로 재해석하지 않으며, 기존 문서와 선택을 유지한다. 이전 `.vrc` 또는 `.iisc` 파일의 전체 읽기는 이전 형식의 서명이 있을 때만 수행한다. 이 동작은 백업 시간 제한을 변경하거나 대형 파일 열기 성능을 보증하지 않는다.

PNG/JPEG/BMP/GIF/TGA/WebP/TIFF/PSD/ORA를 가져온다. PNG/JPEG/BMP/TGA/WebP/TIFF와 레이어 PSD로 내보낸다. PSD 벡터는 PDF 스마트 오브젝트로 내보내며 지원하지 않는 PSD 구성을 평탄화하여 대체하지 않는다. 프로필 사진은 방향 정규화, 중앙 자르기, 원형 알파와 ICC·해상도 메타데이터 보존을 거친다. 표시 및 문서 작업 공간의 RGB ICC 변환은 iiImageCodec이 담당한다.

환경설정과 새 캔버스 창은 주 창의 Core 루프를 공유한다. 한 창을 닫아도 주 창과 다른 창은 유지한다. 웹 계정 연결은 iiAccountManager의 BrowserSession, 보유 확인은 서버 조회, 서명된 업데이트와 보안 저장소는 Native SDK에 연결한다. 계정·라이선스·다른 앱 연결의 관리는 Society에서 수행한다. [웹 로그인 계약](WEB_ACCOUNT.md)을 따른다. 협업은 정규 IISC 문서와 기준 리비전을 전송하며 오래된 편집은 거부한다. 지연 결과는 소유자의 약한 참조와 SDK의 작업 범위를 통하여 닫힌 창에 전달되지 않도록 한다.

기본 가속기는 Mac의 Metal, Windows의 Direct3D이며 Vulkan을 폴백으로 사용한다. Mac에서 강제 Vulkan은 MoltenVK를 통하므로 Metal과 독립된 하드웨어 폴백이라는 의미는 아니다. Windows·Linux는 사용자의 지시에 따라 소스 구현 범위이다. 현재 Mac의 실행 증거와 구분한다. 물리 펜 실기기, 구형 macOS 실기기, 실운영 계정·결제·배포 서버 검증은 자동화된 로컬 검사와 별개이다.

기존 `src/App`은 이행 비교와 기존 작업 보존을 위한 레거시 소스이다. 현재 CMake의 구성·컴파일·링크·리소스·배포 대상에 포함하지 않는다. 이전 빌드 스크립트와 Qt 앱은 `build/native-migration-backup`에 보존한다.

문서 수신을 하나의 이력 명령으로 기록할 때 변경 전후의 선택 레이어를 함께 보관한다. 같은 문서를 다시 받는 무변경 작업은 기존 선택과 이력을 유지한다. 문서 수정·수신·Undo·Redo의 파일 커밋이 거부되면 문서와 이력에 더해 이전 선택을 복원한다. 이 검증 초안은 기존 전체 스냅샷 기반 이력을 사용하며 큰 문서의 Undo 한도 문제를 해결하지 않는다.


창을 열지 않는 캔버스 프레임 회귀는 실행 환경에서 지정한 임시 자원 경로를 사용한다.
테스트 실행기는 그 경로를 `resources/` 아래의 소유 디렉터리로 설정하며, 파일 제공자가
최종 심볼릭 링크를 디렉터리로 취급해야 한다고 가정하지 않는다.

네이티브 테스트 자원 경로는 기본적으로 `resources/` 아래 빌드별 디렉터리이며, CMake의 `CONGREGATION_TEST_RESOURCES`로 같은 자원 트리 안에서 변경할 수 있다. 테스트는 정규화된 실제 경로를 사용하므로 빌드 링크에 대한 파일 제공자의 심볼릭 링크 거부 정책을 우회하지 않는다.

레이어를 삭제할 때 같은 자산을 다른 정적 레이어, 애니메이션 프레임 또는 마스크가 참조하면 해당 자산을 유지한다. 더 이상 어떤 문서 요소도 참조하지 않는 자산만 함께 제거한다. 삭제와 선택은 기존 이력의 한 명령이며 Undo·Redo와 저장·재열기에서 참조와 픽셀이 보존된다.

## 시작 시 라이선스 확인

주 작업 공간을 먼저 표시한다. 계정 기기 정보의 파일 준비와 Society 또는 웹 계정의
라이선스 확인은 별도 백엔드 이벤트 루프에서 수행하고 결과만 UI 이벤트 루프로 전달한다.
iPad에서 UIKit이 소유하는 기기 정보 조회는 주 스레드에서 수행한다. 첫 검증이 진행되는
동안 로컬 문서 편집을 허용하지만, 이는 검증된 라이선스 허가가 아니다. 캔버스 공유와
업데이트처럼 확인된 허가가 필요한 요청은 검증 완료를 기다린다.

검증이 승인되면 작업 공간을 유지한다. 미보유 또는 확인 불가 결과가 먼저 도착해도
작업 공간의 첫 화면 제출을 기다린 뒤 기존 계정·라이선스 안내 화면을 표시한다.
화면 제출 통지를 받을 수 없을 때는 최대 3초 후 전환한다. 결과가 포인터 드래그 중
도착하면 드래그가 끝날 때까지 전환을 미뤄 진행 중인 획과 이력을 보존한다. 계정
안내에서 다시 확인할 수 있으며 기존 작업 문서는 유지된다. 승인된 결정은 현재
실행 동안 유지한다.

## 변경 단위 이력 전환 명세

편집 이력은 변경된 픽셀 타일, 개별 값과 구조 및 필요한 메타데이터만 보관한다. 이력 목적의 전체 문서 직렬화와 복사는 제거 대상이며, 외부 파일 열기·내보내기와 명시적인 협업 문서 전송은 별도 기능이다.

변경과 Undo·Redo는 하나의 순서로 동작한다. 저장 실패·충돌·예산 초과·취소 시 문서, 선택 마스크, 양쪽 스택과 저장 리비전은 바뀌지 않아야 한다. 형식 버전과 작성 정보는 각 이력의 이전·이후 상태에 맞춰 복원한다. 이 절은 전환 목표이며 모든 경로가 이미 전환되었다는 뜻은 아니다.

현재 레이어 이름·가시성·불투명도·변환·혼합 모드는 해당 값과 작성 정보·버전만 이력에 보관하며, 선택 마스크 및 다른 이력과 한 순서로 되돌린다. 현재 모델과 바로 이전 모델, 타일형 작업 파일에서 적용한다. 오디오 트랙, 더 오래된 모델, 레이어 구조·일부 프레임 편집·채우기 등은 아직 전체 스냅샷 또는 문서 복사 경로가 남아 있다. 선택 변경 이력도 마스크의 전체 이전·이후 값에 대한 참조를 보관한다. 파일 게시 시 나머지 문서 메타데이터를 순회하는 비용도 남아 있다.

외부 변경으로 작업 파일 연결이 무효가 되면 일반 편집과 Undo·Redo는 화면의 문서와 이력을 유지한 채 실패를 알린다. 외부 변경과 로컬 이력의 자동 병합이나 연결 복구는 제공하지 않는다.

## 글로벌 Image 메뉴

`App/Application/AppMenu.h`의 `Image` 항목과 구분선은 iiGUI의 네이티브 메뉴 호스트에 전달된다. Mode, Adjustments, Image Rotation, Variables, Analysis는 `No commands available` 비활성 행을 가진 하위 메뉴이다. `Place image…`와 `Draw line`은 마지막 그룹에서 실행할 수 있다.

새 이미지 편집 명령은 콜백이 없는 비활성 항목이다. Auto Tone, Auto Contrast, Auto Color, Image Size, Canvas Size의 단축키 정보는 메뉴 안내용이다. `Congregation.app_menu`는 항목 순서, 구분선, 하위 메뉴, 비활성 상태, 단축키 정보와 기존 명령의 연결을 검사한다.

## 글로벌 File 메뉴

`File` 메뉴는 새 문서와 열기, 닫기와 저장, 내보내기, 이미지 삽입, 자동화와 가져오기, 파일 정보, 인쇄 순으로 묶는다. `New document…`, `Add canvas…`, `Open…`, `Save`, `Save As…`는 기존 문서 명령을 호출한다. `Export` 하위 메뉴의 `Export…`는 기존 내보내기를 열고 `Place Embedded…`는 기존 이미지 삽입을 사용해 문서에 픽셀 레이어를 추가한다.

참고 메뉴에서 Adobe Bridge·Stock, Smart Object 열기와 패키징, Adobe Generator, 클라우드 편집 초대·검토 공유·버전 기록 항목을 제외한다. 구현을 기다리는 명령은 콜백이 없는 비활성 항목이며 단축키는 안내용이다. `Open Recent`, `Automate`, `Scripts`, `Import`는 비활성 안내 행을 가진 하위 메뉴이다. macOS에서는 시스템 앱 메뉴에 종료 명령을 두고 다른 데스크톱에서는 `File` 마지막 그룹에 둔다.

`Congregation.app_menu`는 `File`의 그룹 순서, 하위 메뉴, 단축키 정보와 각 활성 명령의 액션 연결을 검사한다. `Image`에는 같은 검사 방식을 적용한다.

## 글로벌 Edit 메뉴

`Edit`는 실행 취소, Fade, 클립보드, 검색과 텍스트, 채우기와 획, 변형과 레이어 합성, 프리셋 정의, Purge, 일반 프리셋, 색상 관리, 단축키와 환경설정 순으로 묶는다. 참고 메뉴에서는 Adobe PDF Presets와 Photoshop용 Remote Connections만 제외한다. 일반 `Presets`, `Content-Aware Fill…`, `Sky Replacement…`를 포함한 나머지 편집 항목은 메뉴에 표시한다.

`Undo`, `Redo`, `Copy`, `Copy Merged`, `Paste`는 기존 앱 명령을 호출한다. 두 복사 항목은 문서의 합성 이미지를 복사하며 복사와 붙여넣기의 키 입력은 기존 포커스 처리 경로를 사용한다. `Preferences` 하위 메뉴의 `Preferences…`는 기존 설정 창을 연다. 구현을 기다리는 명령은 비활성이고 단축키는 표시용이다. `Paste Special`, `Transform`, `Purge`, `Presets`는 비활성 안내 행을 가진 하위 메뉴이다.

`Congregation.app_menu`는 `Edit`의 그룹과 하위 메뉴, 비활성 명령의 단축키, 기존 액션의 연결을 검사한다.

## 글로벌 Layer 메뉴

`Layer`는 첨부 참고의 14개 그룹을 순서대로 배치한다. Photoshop의 `Smart Objects` 하위 메뉴와 Smart Object에 적용되는 `Smart Filters` 하위 메뉴를 제외한다. 레이어 내보내기, 채우기·조정 레이어, 마스크, 영상·래스터화, 그룹, 정렬, 병합과 매트 항목을 제공한다.

`New > New Layer`, `Duplicate Layer`, `Delete > Delete Layer`는 기존 페인트 레이어 생성, 복제, 삭제 명령을 호출한다. 참고의 숨기기 자리에는 현재 선택 레이어를 표시하거나 숨기는 `Toggle Layer Visibility`를 둔다. `Command/Ctrl + ,`는 환경설정 단축키이며 표시 전환은 메뉴에서 실행한다.

구현을 기다리는 명령은 비활성 항목이고 단축키는 안내용이다. 준비 중인 하위 메뉴에는 비활성 안내 행을 둔다. `Congregation.app_menu`는 전체 순서와 구분선, 하위 메뉴, 단축키 정보, 활성 레이어 명령의 연결을 검사한다.

`Congregation.new_layer_integration`은 큰 문서의 기존 픽셀을 이력 비용에 더하지 않고 작은 레이어를 가져와 되돌릴 수 있는지 확인한다. 가져오기 자체가 이력 예산을 넘으면 문서, 선택과 이력을 보존하는지도 검사한다.

## 글로벌 Select 메뉴

`Select`는 기본 선택, 레이어 선택, 영역 탐색, 선택 마스크와 수정, 확장과 유사 영역, 변형, Quick Mask, 선택 저장·불러오기, 3D 돌출 순으로 묶는다. 준비 중인 명령은 비활성 항목이며 `Modify` 하위 메뉴에는 비활성 안내 행을 둔다.

`Deselect`와 `Inverse`는 기존 선택 마스크 편집 명령을 호출한다. `Deselect`의 키 조합은 `Command/Ctrl + D`이고 비활성 `Reselect`의 `Command/Ctrl + Shift + D`와 구분한다. `Inverse`는 `Command/Ctrl + Shift + I`로 실행하며 텍스트 입력에 포커스가 있으면 캔버스 선택을 보존한다.

`Edit in Quick Mask Mode`는 도구 모음과 같은 진입·적용 경로를 사용한다. `Q`는 기존 도구 입력 처리로 전달된다. `Congregation.app_menu`는 메뉴 순서와 액션을 확인하고 `Congregation.quick_mask_integration`은 마스크 편집, 적용, 취소와 Undo/Redo를 검사한다.

## 글로벌 Filter 메뉴

`Filter`는 `Gaussian Blur`, `Generative filter`, 개별 필터 명령, 필터 분류 하위 메뉴 순으로 묶는다. 참고의 `Neural Filters…` 자리는 `Generative filter`로 표기한다. Adobe 전용 `Convert for Smart Filters`와 `Camera Raw Filter…`는 제외한다.

필터 실행 명령은 콜백이 없는 비활성 항목이며 하위 메뉴에는 비활성 안내 행을 둔다. 단축키는 안내용이다. 참고의 `Command/Ctrl + Shift + R`은 앱의 수직 대칭 그리기 단축키로 사용하므로 `Lens Correction…`은 키 표기 없이 배치한다. `Congregation.app_menu`는 명칭, 순서와 구분선, 하위 메뉴, 비활성 상태와 단축키 정보를 검사한다.

## 글로벌 View 메뉴

`View`는 교정 색상과 픽셀 종횡비, 배율과 화면 맞춤, 화면 모드, 표시 요소, 눈금자, 스냅, 안내선, 분할 영역 순으로 묶는다.
`Zoom In`, `Zoom Out`, `Fit on Screen`은 기존 캔버스 배율 명령을 호출한다. `Screen Mode > Presentation`은 프레젠테이션 모드를 전환한다.
`Rulers`는 기존 `Command/Ctrl + R`과 같은 눈금자 전환을 사용한다.

`Fit on Screen`의 키 조합은 `Command/Ctrl + 0`이다. 준비 중인 명령은 비활성 항목이고 단축키는 안내용이다.
`Extras`의 안내는 macOS 앱의 표준 `Command + H`와 구분하도록 `Control + H`를 사용한다.
준비 중인 하위 메뉴는 비활성 안내 행을 표시한다.

`Congregation.app_menu`는 `View`의 순서, 구분선, 하위 메뉴, 활성 상태, 단축키와 기존 명령의 연결을 검사한다.

## 글로벌 3D 메뉴

`Filter`와 `Window` 사이에 최상위 `3D` 메뉴를 둔다. 30개 항목을 3D 레이어와 파노라마,
콘텐츠 내려받기, 돌출과 메시 생성, 장면의 개체 배치, UV와 텍스처 페인팅, 형상 편집, 렌더링, 3D 인쇄 순으로 묶는다.

3D 작업 명령은 비활성 상태로 표시한다. `Spherical Panorama`, `New Mesh from Layer`, `Paint System`,
`Paint on Target Texture`, `Create Painting Overlay` 하위 메뉴에는 비활성 안내 행을 둔다.
`Render 3D Layer`의 단축키 표기는 `Command/Ctrl + Option/Alt + Shift + R`이다.

`Congregation.app_menu`는 최상위 위치, 항목 순서와 구분선, 하위 메뉴, 비활성 상태와 단축키 표기를 검사한다.
