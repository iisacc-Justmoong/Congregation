# Qt 없는 Congregation 실행 구조

## 시작 캔버스 크기

앱이 새 시작 캔버스를 만들 때는 창이 실제로 표시되는 디스플레이의 현재 픽셀
해상도와 방향을 사용한다. 작업 가능 영역이나 창 크기로 대체하지 않으며 가로·세로
비율도 그대로 유지한다. 기존 문서 복구 또는 명시적 파일 열기에 성공했다면 해당
문서의 크기를 유지한다. 디스플레이가 아직 결정되지 않은 경우에는 값이 준비될 때까지
대기하고, 값을 확인할 수 없거나 문서 크기 제한을 넘으면 잘못된 크기의 캔버스를
만드는 대신 오류를 표시한다. 새 캔버스의 Society Files 저장 계약은 유지한다.
출력 정보가 늦게 도착하는 경우 최대 5초 동안 확인하며, 기다리는 동안 사용자가
기존 문서를 열거나 협업 문서를 받으면 그 문서를 새 시작 캔버스로 교체하지 않는다.

## Society 새 캔버스 저장 계약

새 캔버스의 작업 파일은 선택된 Society 저장소의 `Files` 안에 고유 이름으로 만든다.
첫 저장과 다른 이름으로 저장은 사용자가 `Files` 아래의 경로를 명시적으로 선택해야
하며, 임시 작업 파일을 정식 저장 경로로 오인하지 않는다. 기존 파일·다른 저장소·
리디렉션된 경로를 임시 파일로 취급하거나 자동 삭제하지 않는다. 데스크톱에서
저장소를 확인할 수 없으면 새 캔버스 생성을 실패로 보고한다. 모바일에서 Society
시스템 저장소가 없으면 iiSocietyContainer가 앱 샌드박스에 별도의
`Society.societycontainer`를 만들고 그 안의 `Files`를 사용한다. 이 앱별 컨테이너는
OS의 Society 드라이브로 등록하거나 다른 앱과 공유하지 않는다.

새 캔버스를 닫거나 교체할 때는 기본 배경과 초기 문서 구조 이외의 작업 내용이
정말 없는 경우에만 소유한 임시 파일을 삭제한다. 내용·문서 구조·파일 소유권이나
저장소 식별을 확실히 확인할 수 없다면 보존한다. 명시 저장된 파일과 내용이 있는
미저장 파일은 보존하고, 저장·생성 실패는 기존 문서와 파일을 유지한다. 비정상 종료
뒤에 소유권을 증명할 수 없는 파일을 자동 삭제하지 않는다.
초기 상태 비교는 생성과 정리 시에 수행하며 펜 입력이나 매 획마다 문서 전체를
복사하거나 검사하지 않는다.

첫 저장에는 운영체제 저장 대화상자를 사용하고 `Files` 하위의 `.iisc` 경로만
허용한다. 명시 저장 뒤에는 작업 파일과 저장 파일의 내용 및 식별자가 일치하고 그
뒤에 수정되지 않은 경우에만 작업 파일을 정리한다. 그림을 그리거나 문서를 수정한
뒤 저장하지 않았다면 작업 파일은 `Files`에 남는다. 데스크톱에서 저장소가 연결되지
않았거나 모바일에서 앱별 저장소도 준비하지 못한 경우에는 안내용 빈 화면을 표시하고
편집을 막으며, 새 캔버스 또는 파일 열기는 다시 시도할 수 있다. 저장소 선택 파일과
실제 컨테이너가 다른 경우에도 작업 파일을 보존한다.

데스크톱의 선택된 Society 저장소와 모바일 앱별 저장소를 인식한다. iPad에서 서명된
Society App Group에 유효한 시스템 저장소가 나타나면 시작 시 백그라운드 작업으로
앱별 컨테이너의 내용을 복사한다. 충돌 파일은 이름을 구분하고 원본은 보존하며,
진행 중인 데이터베이스나 리디렉션이 확인되면 이관을 미루고 앱별 저장소를 유지한다.
공용 저장소 접근은 App Group 서명과 해당 기기의 Society 준비 상태에 좌우된다.
iPad의 명시적 파일명 저장 대화상자는 아직 제공하지 않는다. Android 앱별 저장소는
같은 API로 만들 수 있지만 Society의 ContentProvider를 통한 자동 이관은 아직 연결하지
않았다. Society가 없는 기기에서 만들어 보존한 작업 파일은 최근 문서에 자동 등록되지
않으며, 공용 저장소 이관 대상에는 포함된다.

실행 소스는 `App/Engine`과 `App/Native`이다. 앱 진입점·이벤트 루프·작업 수명은 iiSDKCore가 소유하고 iiGUI Host가 운영체제 창에 연결한다. `App/Native/views/*.lvui`는 `Window`, `HStack`, `VStack`과 컨트롤을 중첩해 직접 선언하고 빌드 시 C++23으로 생성한다. 상태와 이벤트는 import한 C++ 뷰모델에 연결한다. HTML 태그와 CSS형 인라인 스타일을 사용하지 않으며 LVRS, 브라우저·WebView·Qt·QML 엔진을 링크하지 않는다.

`EditorBackend`의 목록은 독립 LVUI `ListSource`와 반응형 리비전을 제공한다.
공유 색상도 관찰 가능한 값과 명령으로 노출한다. 제품 상태에서 생성한 행은
LVUI 목록 원본으로 전달된다. 뷰모델과 현재 화면의 구현 범위는
[LVUI 뷰모델 계약](LVUI_VIEWMODELS.md)을 따른다.

`Artwork`는 제품의 도구·실행 취소 정책이다. 문서, 픽셀, 벡터, 변환, 타일 합성과 파일 편집은 iiSharedCanvas Native에 위임한다. 파일과 SQLite는 iiFileProvider가 소유한다. 펜 입력은 한 스트로크당 한 문서 커밋이며 취소하면 미리보기 픽셀을 되돌린다. 확대·이동·선택·프로필·브러시 설정은 저장 문서의 리비전을 바꾸지 않는다. 실행 취소는 최대 32개 명령, 직렬화 스냅샷 합계 64 MiB로 제한한다.

제품은 유한 캔버스를 사용한다. iPad의 손가락 입력은 운영체제가 표본을 전달하고
iiSDKCore와 iiGUI가 이동·핀치 제스처를 해석한다. 캔버스는 전달된 내용 이동량을
사용하며 포인터 취소 시 진행 중인 획을 되돌린다. 손을 뗀 뒤의 관성과 중단·감속은
앱별 계산 없이 iiSDK의 입력 및 프레임 시계가 처리한다. 휠 입력은 기존 동작을 유지한다.
iPad의 콘텐츠는 iiGUI 창의 전체 영역을 사용해 상단과 하단 시스템 표시 영역 아래까지
확장된다. 분할 화면에서는 실제 장면 창의 크기를 따른다.
화면은 보이는 영역만 최대 512픽셀 타일로 전달한다. 레이어 추가·삭제·복제·이름·가시성·순서와 벡터 도형, 텍스트 배치, 이미지 가져오기를 제공한다. 선택 도구에서 드래그는 이동, Shift 드래그는 배율, Alt 드래그는 회전이다. Space 또는 가운데 버튼은 화면 이동이며 Control/Meta+Space 드래그는 임시 확대이다. 텍스트 입력에 포커스가 있으면 캔버스 단축키와 메뉴 실행 취소를 억제한다.

저장은 이식 가능한 `.iisc`이며 작업 복구본은 별도 SQLite 문서이다. 최근 복구 설정은 앱의 관리 디렉터리에 있는 정규 UUID 이름의 일반 파일만 허용한다. 이전 `.vrc`는 내부 IISC, 내장 PNG, 래스터 레이어 및 도형을 읽고 개별 네이티브 레이어로 이행한다. 이전 텍스트는 네이티브 글꼴로 그린 비트맵 레이어가 된다. 알 수 없는 개체·누락된 픽셀·지원하지 않는 합성은 거부하며 원본을 덮어쓰지 않는다.

열기에서는 파일의 짧은 서명으로 네이티브 IISC·SQLite 문서를 식별한다. 네이티브 읽기에 실패하면 그 오류를 전달하고 이미지 가져오기로 재해석하지 않으며, 기존 문서와 선택을 유지한다. 이전 `.vrc` 또는 `.iisc` 파일의 전체 읽기는 이전 형식의 서명이 있을 때만 수행한다. 이 동작은 백업 시간 제한을 변경하거나 대형 파일 열기 성능을 보증하지 않는다.

PNG/JPEG/BMP/GIF/TGA/WebP/TIFF/PSD/ORA를 가져온다. PNG/JPEG/BMP/TGA/WebP/TIFF와 레이어 PSD로 내보낸다. PSD 벡터는 PDF 스마트 오브젝트로 내보내며 지원하지 않는 PSD 구성을 평탄화하여 대체하지 않는다. 프로필 사진은 방향 정규화, 중앙 자르기, 원형 알파와 ICC·해상도 메타데이터 보존을 거친다. 표시 및 문서 작업 공간의 RGB ICC 변환은 iiImageCodec이 담당한다.

환경설정과 새 캔버스 창은 주 창의 Core 루프를 공유한다. 한 창을 닫아도 주 창과 다른 창은 유지한다. 웹 계정 연결은 iiAccountManager의 BrowserSession, 보유 확인은 서버 조회, 서명된 업데이트와 보안 저장소는 Native SDK에 연결한다. 계정·라이선스·다른 앱 연결의 관리는 Society에서 수행한다. [웹 로그인 계약](WEB_ACCOUNT.md)을 따른다. 협업은 정규 IISC 문서와 기준 리비전을 전송하며 오래된 편집은 거부한다. 지연 결과는 소유자의 약한 참조와 SDK의 작업 범위를 통하여 닫힌 창에 전달되지 않도록 한다.

기본 가속기는 Mac의 Metal, Windows의 Direct3D이며 Vulkan을 폴백으로 사용한다. Mac에서 강제 Vulkan은 MoltenVK를 통하므로 Metal과 독립된 하드웨어 폴백이라는 의미는 아니다. Windows·Linux는 사용자의 지시에 따라 소스 구현 범위이다. 현재 Mac의 실행 증거와 구분한다. 물리 펜 실기기, 구형 macOS 실기기, 실운영 계정·결제·배포 서버 검증은 자동화된 로컬 검사와 별개이다.

기존 `src/App`은 이행 비교와 기존 작업 보존을 위한 레거시 소스이다. 현재 CMake의 구성·컴파일·링크·리소스·배포 대상에 포함하지 않는다. 이전 빌드 스크립트와 Qt 앱은 `build/native-migration-backup`에 보존한다.

문서 수신을 하나의 이력 명령으로 기록할 때 변경 전후의 선택 레이어를 함께 보관한다. 같은 문서를 다시 받는 무변경 작업은 기존 선택과 이력을 유지한다. 문서 수정·수신·Undo·Redo의 파일 커밋이 거부되면 문서와 이력에 더해 이전 선택을 복원한다. 이 검증 초안은 기존 전체 스냅샷 기반 이력을 사용하며 큰 문서의 Undo 한도 문제를 해결하지 않는다.


창을 열지 않는 캔버스 프레임 회귀는 실행 환경에서 지정한 임시 자원 경로를 사용한다.
테스트 실행기는 그 경로를 `resources/` 아래의 소유 디렉터리로 설정하며, 파일 제공자가
최종 심볼릭 링크를 디렉터리로 취급해야 한다고 가정하지 않는다.

네이티브 테스트 자원 경로는 기본적으로 `resources/` 아래 빌드별 디렉터리이며, CMake의 `CONGREGATION_TEST_RESOURCES`로 같은 자원 트리 안에서 변경할 수 있다. 테스트는 정규화된 실제 경로를 사용하므로 빌드 링크에 대한 파일 제공자의 심볼릭 링크 거부 정책을 우회하지 않는다.

레이어를 삭제할 때 같은 자산을 다른 정적 레이어, 애니메이션 프레임 또는 마스크가 참조하면 해당 자산을 유지한다. 더 이상 어떤 문서 요소도 참조하지 않는 자산만 함께 제거한다. 삭제와 선택은 기존 이력의 한 명령이며 Undo·Redo와 저장·재열기에서 참조와 픽셀이 보존된다.

## 시작 시 라이선스 확인

주 작업 공간을 먼저 표시한다. 계정 기기 정보의 파일 준비와 Society 또는 웹 계정의
라이선스 확인은 별도 백엔드 이벤트 루프에서 수행하고 결과만 UI 이벤트 루프로 전달한다.
iPad에서 UIKit이 소유하는 기기 정보 조회는 주 스레드에서 수행한다. 첫 검증이 진행되는
동안 로컬 문서 편집을 허용하지만, 이는 검증된 라이선스 허가가 아니다. 캔버스 공유와
업데이트처럼 확인된 허가가 필요한 요청은 검증 완료를 기다린다.

검증이 승인되면 작업 공간을 유지한다. 미보유 또는 확인 불가 결과가 먼저 도착해도
작업 공간의 첫 화면 제출을 기다린 뒤 기존 계정·라이선스 안내 화면을 표시한다.
화면 제출 통지를 받을 수 없을 때는 최대 3초 후 전환한다. 결과가 포인터 드래그 중
도착하면 드래그가 끝날 때까지 전환을 미뤄 진행 중인 획과 이력을 보존한다. 계정
안내에서 다시 확인할 수 있으며 기존 작업 문서는 유지된다. 승인된 결정은 현재
실행 동안 유지한다.
