# iiSDKCore 기반 앱 엔진

Congregation의 실행 소스는 도메인별 `App/`에 있으며 [소스 구조](APP_DOMAINS.md)에 정리되어 있다. 최종 진입점, 이벤트 루프, 작업 수명은 iiSDKCore가 소유한다. iiGUI Host는 같은 Core 루프를 네이티브 창과 GPU 표시 경로에 연결한다. Qt 호스트·QObject 어댑터·QML 엔진은 현재 실행 경로에 없다.

## 소유 관계

| 소유자 | 책임 |
| --- | --- |
| `ApplicationEngine` | 소유 또는 차용한 Core EventLoop, TaskScope, 시작·종료와 제품 서비스 수명 |
| `CanvasDocument`, `Palette` | 타입이 있는 QueryPort, 브러시·압력·도구·팔레트 상태 |
| `CanvasSession`, `NearbyDiscovery` | TCP 협업, 정규 문서·기준 리비전, 멤버·초대와 LAN 탐색 |
| `Preferences`, `RecentCanvas` | 설정 이행·원자적 저장, 복구 경로 검증과 이전 컨테이너 해석 |
| `LicenseService` | 라이선스 검증 정책, 보안 저장소 복원·삭제·재시도 |
| `EditorBackend` | LVUI 스코프가 소유하는 Core Observable 값, UI 명령과 목록·색상 모델 |
| `Artwork` | 제품 도구와 실행 취소 정책, SharedCanvas 문서 명령 |
| `CanvasView` | 문서 좌표와 화면 좌표, 보이는 타일·입력·선택 표시 |
| `State` | 주 창·보조창, 메뉴·대화상자와 서비스 결과 연결 |

Core를 하위 기반으로 사용하며 Core에서 앱·GUI·문서를 참조하지 않는다. 문서의 파일·SQLite 소유자는 iiFileProvider이고 픽셀·레이어·변환·합성·파일 형식 소유자는 iiSharedCanvas Native이다. 이미지 코덱과 ICC 변환은 iiImageCodec에 둔다. 계정·라이선스·서명된 업데이트·보안 저장소는 각 Native SDK를 사용한다.

## 실행과 해제

GUI 실행은 Core Application의 이벤트 루프를 엔진에 차용한다. 차용한 엔진을 종료할 때에는 자기 TaskScope만 닫고 공유 루프는 유지한다. 엔진 단독 생성자는 자신의 루프를 소유하며 함께 닫는다. 주 창·환경설정·새 캔버스 보조창은 하나의 Core 루프를 공유한다. 보조창 표시 콜백은 비동기적으로 도착하므로 `show()` 직후 마운트가 완료되었다고 가정하지 않는다.

HTTP·TCP·UDP·예약 작업은 Core 수명과 네이티브 iiNetwork에 연결한다. 서비스 결과는 약한 소유 참조와 작업 취소를 거쳐 전달하며 이미 해제된 뷰를 갱신하지 않는다. 파일 선택은 운영체제의 비동기 대화상자를 사용한다. 웹 이미지 가져오기는 HTTP(S), 16 MiB·15초·리디렉션 3회로 제한하며 대상 문서가 바뀌면 결과를 적용하지 않는다.

LVUI는 중첩된 View와 바인딩 선언을 빌드 시 C++23으로 생성한다. 백엔드를 구성한 뒤 위젯을 생성하여 같은 목록·색상 모델을 주입한다. `vm.method`는 지연 콜백 참조이고 `vm.method()`는 호출이다. Core Observable과 위젯 BindingScope가 변경 통지와 구독 해제를 담당한다.

## 문서와 편집

완성된 스트로크 하나는 문서 변경 하나이다. 미리보기 중 취소·포커스 상실·잘못된 브러시는 이전 픽셀과 캔버스 범위를 복원한다. Congregation은 유한 캔버스를 사용한다. 화면 이동·확대·레이어 선택·한 픽셀 조회·브러시 설정은 문서 리비전·dirty·저장을 바꾸지 않는다.

저장 파일은 이식 가능한 정규 `.iisc`이며 작업 복구용 SQLite는 앱의 관리 디렉터리에 별도로 둔다. 복구본을 열어도 내부 파일을 사용자의 저장 대상 경로로 설정하지 않는다. 이전 `.vrc`는 확인 가능한 개별 레이어·도형·텍스트를 이행하며 알 수 없는 개체·잘못된 식별자·누락 데이터는 원본 변경 없이 거부한다.

협업 프로토콜 2는 참가자마다 초기 연결에서 한 번만 정규 IISC 체크포인트를 읽는다. 새 참가자가 도착하면 호스트의 작업 파일에 확정된 리비전에서 초기본을 얻는다. 연결이 수립된 참가자에게는 `CanvasSession`이 오름차순 리비전과 정확한 편집 이벤트를 전달한다. 프로필·초대·참가자 알림은 문서 리비전을 바꾸지 않는다.

빌드와 실행 증거는 [BUILD.md](BUILD.md), [NATIVE_VERIFICATION.md](NATIVE_VERIFICATION.md)에 있다. 세부 제품 계약은 [NATIVE_RUNTIME.md](NATIVE_RUNTIME.md)에 있다.

### 런타임의 문서 변경

iiSharedCanvas Native 0.35.41의 편집 이벤트에는 바뀐 레이어 레코드와 배치, 프레임 소유 키, 자산, 아트보드·오디오·타이밍, 64×64 래스터 타일과 청크 생성·삭제를 기록한다. 새 미디어에는 해당 자산을 포함한다. Undo/Redo 스택은 영역 저널 또는 순방향·역방향 이벤트를 사용한다. 수신 측은 작업 파일 쓰기에 성공한 후 이벤트와 리비전을 확정한다. 같은 문서 영역의 편집은 수신자의 레이어 선택과 선택 마스크를 유지한다. 캔버스 범위가 바뀌어 맞지 않게 된 선택 마스크는 이력에 보관한다.

캔버스는 변경 전후의 레이어 위치·참조·클리핑을 반영해 영향을 받는 프레임과 타일을 무효화한다. 타임라인은 해당 레이어의 프리뷰와 행을 갱신하며 유지되는 프리뷰를 다시 렌더링하지 않는다. 목록, 타이밍 및 캔버스 크기 바인딩은 해당 속성이 바뀌었을 때 통지한다. 문서 초기화에는 새 캔버스, 다른 파일 열기, 협업 합류가 포함된다.

### 협업 전송과 실패 복구

초기본 뒤의 모든 이벤트는 참가자별 송신 대기열에서 순서대로 처리한다. 참가자는 초기본 적용이 완료된 뒤부터 편집을 제출할 수 있다. 클라이언트의 다음 편집은 현재 편집에 대한 호스트의 정확한 확인을 기다린다. 송신·재시도 예산을 넘기거나 동일 기준 리비전에서 경쟁하는 편집이 발생하면 해당 연결에 오류를 알리고 로컬 복구 파일을 유지한다. 저장이 거부되거나 실패하면 문서·선택·Undo/Redo 위치와 협업 리비전을 보존한다.

자동 검사는 로컬 TCP에서 초기 동기화, 런타임 변경 순서, 호스트 및 게스트 편집과 이력, 프로필 갱신, 늦은 합류, 잘린 이벤트와 저장 실패 복구를 다룬다.
