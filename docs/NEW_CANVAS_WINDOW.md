# New canvas 서브윈도우

Congregation의 새 캔버스 창은 Dreamscapes의 `NewCanvasDialog.qml`과
`CanvasSizePreview.qml`을 기준으로 내용·레이아웃·입력 동작을 공유한다.
Dreamscapes는 편집 화면 위의 모달 팝업이며 Congregation은
`ii::gui::Host::show(parent, callbacks)`로 여는 비모달 네이티브 서브윈도우이다.
메인 문서에는 어두운 덮개를 올리지 않으며 서브윈도우를 연 상태에서도 편집할 수 있다.
이미 열린 창에서 New 명령을 다시 실행하면 같은 창을 앞으로 가져온다.

## 구성과 크기

초기 클라이언트 영역은 1280 × 880이며 최소 크기는 320 × 480이다.
바깥 여백은 12이며 콘텐츠 바깥에 별도의 테두리는 그리지 않는다. 운영체제가
제공하는 창 프레임은 유지한다. 창과 패널은 LVUI의 공통 창·표면 색상을
사용하며 Pretendard와 LVUI 위젯을 사용한다. 크기와 간격 일부는 현재 제품의
`Layout.lvui`에 남아 있으므로 공통 LVUI 토큰과 레이아웃 책임으로 옮겨야 한다.

- 너비 1000 이상: 높이 96인 헤더, 200 너비의 카테고리 목록, 최대 3열 카드 갤러리,
  268 너비의 상세 패널, 높이 68인 푸터를 배치한다. 본문 여백과 열 간격은 24이다.
- 너비 1000 미만: 헤더 높이 132, 푸터 높이 94, 본문 여백 12로 전환한다.
  카테고리는 헤더의 메뉴에서 선택하며 갤러리와 상세 설정을 하나의 본문에서 스크롤한다.
- 카드 높이는 144, 미리보기 높이는 62, 정적인 이름·치수 영역은 44이다.
  카드 열 수는 `clamp(floor((galleryWidth + 12) / 220), 1, 3)`이다.
- 상세 미리보기 높이는 124, 사용자 지정 미리보기 높이는 일반 창에서 320,
  좁은 창에서 180이다. 직사각형은 픽셀 종횡비를 유지한다.

검색·Custom size·Close, 카테고리 목록, 카드, Canvas details,
선택 요약·배경 요약·Cancel·Create canvas의 문구와 순서를 원본에 맞춘다.
네이티브 창의 제목 표시줄과 운영체제 창 조작은 Congregation의 서브윈도우 방식에 따른다.

## 프리셋과 생성 규칙

`resources/canvas-presets.json`은 Dreamscapes revision 3의 원본과 바이트 단위로 같은
14개 카테고리·289개 프리셋 스냅샷이다. 출처·해시는
`resources/canvas-presets-source.json`에 기록한다. 빌드 때 C++ 상수로 포함하므로
실행 시 Dreamscapes 설치본이나 소스 경로를 참조하지 않는다.
데이터는 274개의 starter 항목과 15개의 출처가 있는 documented-recommendation 항목을 유지한다.

```sh
python3 -B tools/sync_canvas_presets.py --check
# Dreamscapes 원본을 검토하고 갱신하는 경우
python3 -B tools/sync_canvas_presets.py
```

검색은 모든 카테고리를 대상으로 플랫폼·용도·크기·단위를 찾는다.
`1920 × 1080`과 `1920x1080`을 같은 치수 검색으로 처리하며 독립된 검색어 `X`는
해당 플랫폼으로 한정한다. 검색 결과나 카테고리를 바꾸면 첫 프리셋을 선택한다.
결과가 없으면 생성 버튼을 비활성화하고 Clear search를 제공한다.
일반·축소 화면의 지우기는 LVUI 입력 필드의 사용자 편집으로 처리한다. 지운 검색어는
해당 입력의 실행 취소·재실행으로 복구할 수 있으며 지운 뒤에도 입력 포커스를 유지한다.
일반·축소 입력의 아이콘과 지우기 버튼은 LVUI의 `NativeSearchField`가 소유하고
기존 접근성·자동화 식별자를 보존한다. 모델의 다른 상태가 갱신되어도 검색어의 미확정
조합을 유지한다. 검색 표면은 LVUI의 배경 블러·그라디언트·테두리와 근사된 안쪽
그림자를 사용한다. 실제 GPU 화면의 Figma 동등성과 키보드 포커스 구분은 미검증이다.

사용자 지정은 1800 × 1200 px, 300 PPI로 시작하며 1:1, 16:9, 9:16 단축 크기를 제공한다.
단위는 px·mm·in이다. 단위 변경은 현재 물리적 크기를 변환하며 인쇄 단위에서 PPI와
변환된 픽셀 치수를 표시한다. px는 정수만 허용한다. 각 축은 최대 32768 px,
전체 면적은 268435456 px이며 PPI는 양수이면서 2400 이하이다.
인쇄 단위에서 정확히 반 픽셀이 발생하면 짝수 쪽으로 반올림하여 원본과 같은 값을 낸다.

배경은 White·Transparent·Black이다. White와 Black은 캔버스 전체의 벡터 배경 레이어,
그 위에는 투명한 Paint layer를 만든다. Transparent는 Paint layer만 만든다.
문서 크기와 배경은 IISC 저장·재열기 뒤에도 유지한다. 프리셋 이름·분류·물리 단위·PPI는
Dreamscapes와 같이 생성 세션의 정보이며 기존 IISC 파일 형식에 새 메타데이터를 추가하지 않는다.

Cancel·Close·Escape·창 닫기는 작업 중인 문서를 교체하지 않는다.
검증에 실패하거나 생성에 실패하면 입력 창에 오류를 표시하고 기존 문서를 유지한다.
생성에 성공하면 편집 대상과 문서 제목을 갱신하고 서브윈도우를 닫는다.
Find 단축키는 검색창에 초점을 주고 Control/Command + Return은 유효한 문서를 생성한다.
카드는 키보드로 선택할 수 있고 화면 밖의 카드에 초점을 주면 해당 항목을 스크롤해 보여 준다.

## 구조와 검증

`CanvasCatalogue`는 불변 데이터·검색·변환·검증을, `CanvasSetupModel`은 선택과 입력 상태를,
`CanvasSetupWindow`는 LVUI·iiGUI 컨트롤 배치와 입력 전달을 맡는다.
`CanvasDefinition`은 편집 정책에 전달하는 데이터 계약이다.
기존 `EditorBackend`의 별도 크기 입력 모델은 제거해 중복된 검증을 없앴다.
LVUI는 창 옵션과 모델 수명을 빌드 때 생성하며 Qt·QML 실행기를 포함하지 않는다.

갤러리의 배경·선택선·종횡비 미리보기는 보이는 영역에 한해 하나의 그리기 목록으로 묶는다.
각 카드는 별도의 네이티브 동작·접근성·키보드 포커스를 유지한다.
카테고리·갤러리 변경은 해당 본문만 교체하며 검색 입력과 상세 입력의 초점은 보존한다.
새 본문을 구성할 때 갤러리도 같은 생성 단계에 포함하므로 위젯 트리의 중첩 교체가
진행 중인 세대를 건드리지 않는다. 헤드리스 검사는 실제 제품의 본문 구성 함수를
호출해 검색과 입력, 좁은 화면의 카테고리 메뉴와 넓은 화면 복귀를 확인한다.
폭 입력의 더블 클릭 선택과 입력값 교체도 실제 LVUI 입력 필드를 사용해 검사한다.

```sh
cmake --build build --parallel 4
ctest --test-dir build -R 'canvas_|artwork|ui_style_tokens' --output-on-failure
ctest --test-dir build --output-on-failure
```

`Congregation.canvas_reference`는 원본 데이터와 디자인 치수의 추적성을,
`canvas_setup`은 289개 항목·전역 검색·단위 변환·경계값을 검사한다.
`canvas_window_native`와 `canvas_window_vulkan`은 실제 부모·자식 창에서 레이아웃,
입력·포커스·생성 제한·리사이즈·스크롤·독립 닫기를 검사하고
`build/new-canvas/{native,vulkan}/`에 화면을 저장한다.
`artwork`는 배경 렌더링·저장·재열기·실패 시 문서 보존을 검사한다.
전체 standalone·bundle relocation 검사는 실제 앱에서 같은 생성 흐름과
Qt 없는 배포 번들의 독립 실행을 검사한다.

## 2026-11-03 양 끝 표시 이식 후 확인

LVUI가 독립 슬라이더의 선택적인 양 끝 레이블·아이콘과 그에 따른 입력 범위를
지원하도록 확장된 뒤, 해당 스테이징 설치본으로 macOS arm64 Debug의 전체
Congregation 빌드를 다시 마쳤다. 이는 새 캔버스 창에 양 끝 표시를 추가했다는
뜻은 아니다. Qt5·Qt6·LVRS 패키지 탐색은 끄고 검색 환경 변수를 제거했으나 기존
iiSDK 경로와 빌드 캐시는 재사용했다.

창을 열지 않는 제품 회귀 101건과 LVUI 헤드리스 회귀 630건, LVUI 이동 설치
소비자·패키지 경계 검사 2건이 통과했다. 소비자는 반응형 양 끝 표시가 포함된
슬라이더와 검색 필드를 생성·컴파일·링크했다. 실제 창·GPU와 앱 번들 이동 실행을
필요로 하는 제품 검사 9건 및 설치 소비자 GUI는 실행하지 않았다.

앱 번들의 Mach-O 7개에서 자체 식별자를 제외한 동적 의존성 62행과 `nm -m`
심볼 225,393행에 검사한 Qt·LVRS 이름은 없었다. `@rpath` 참조 7행은 번들에
존재하며 로컬 임시 서명도 유효했다. 주 실행 파일 SHA-256은
`0694130b57358f0d725f3156ebb7b0f510eb0b4902ff8e21ed5961245355bdde`이다.
이는 이름과 경로에 대한 정적 검사이며 숨겨진 정적 코드의 전체 출처나 실제 실행을
증명하지 않는다.

## 2026-11-03 이전 LVUI 설치본 확인

검색 필드와 슬라이더의 최신 독립 LVUI 설치본으로 macOS arm64 Debug의 전체
대상을 다시 빌드했다. Qt5·Qt6·LVRS 패키지 탐색은 비활성화했고 컴파일러·
라이브러리 검색 환경 변수는 제거했다. 기존 iiSDK 패키지 경로와 빌드 캐시는
재사용했으므로 파일 시스템 전체를 격리한 클린 빌드는 아니다.

창을 열지 않는 제품 회귀 101건이 모두 통과했다. 실제 창·GPU와 앱 번들 이동
실행이 필요한 9건은 실행하지 않았다. LVUI는 별도로 헤드리스 회귀 630건과
이동 설치 소비자·패키지 경계 검사 2건이 통과했다. 설치 소비자는 검색 필드와
눈금·심볼이 있는 슬라이더의 생성 코드와 기본 아이콘 자산을 컴파일·링크했고
실제 GUI는 실행하지 않았다.

최신 앱 번들의 Mach-O 이미지 7개에서 dylib 자체 식별자를 제외한 의존성 62행과
`nm -m` 심볼 225,128행을 검사했으며 Qt·LVRS 이름은 찾지 못했다. `@rpath` 의존성
7행에 해당하는 파일은 모두 번들 안에 있고 로컬 임시 서명도 유효하다. 이는 검사한
이름과 경로에 대한 정적 증거이며 모든 정적 코드의 출처나 이동 실행을 증명하지는
않는다. 주 실행 파일 SHA-256은
`2b908e1d6b15ab08f241ca8045bf68f413b28f028f6c77dcd82b8ef72ee784fe`이다.

## 2026-11-03 입력 이력과 독립 빌드 확인

Qt5·Qt6·LVRS 패키지 탐색을 비활성화한 macOS arm64 Debug 전체 빌드가
성공했다. 창을 열지 않는 제품 검사 101건이 모두 통과했으며, 그중 새 캔버스의
일반·축소 검색 필드에서 입력, 지우기, 포커스 유지와 Undo/Redo를 검사했다.
실제 창·GPU 또는 이전 위치에서 옮긴 앱을 실행하는 검사 9건은 이번에 실행하지 않았다.

생성된 앱 번들의 Mach-O 7개, 동적 라이브러리 항목 70개 및 `nm -m` 심볼 행
224,172개에서 검사한 Qt·LVRS 이름을 찾지 못했고 로컬 임시 서명을 확인했다.
주 실행 파일 SHA-256은
`356ec0ecc90d9f09e992350f7dcbf4094b4590518479e9a6bc3f97fadd8d76ca`이다.
이는 해당 빌드의 정적 분석이며 실제 실행이나 모든 정적 코드의 부재를 증명하지 않는다.

## 2026-10-25 최종 결과

macOS arm64 Release 정식 앱 빌드와 제품 전체 CTest **21/21**이 통과했다.
실행 시간은 277.66초이며 건너뛴 검사는 없다. Metal·Vulkan 양쪽에서 새 창과 기존 Main 화면을
실제로 열어 검사했다. 새 창은 1280 × 880, 640 × 480, 390 × 844, 320 × 640에서
레이아웃·스크롤과 화면 캡처를 확인했다.

실제 메뉴를 통한 단위·배경 선택, 검색 입력과 원형 지우기 버튼, 폭·PPI 입력 중 초점 보존,
오류 시 생성 비활성화, Control + Return, 화면 밖 카드로의 포커스 이동을 확인했다.
서브윈도우가 열려 있는 동안 부모 창 입력이 가능하고 자식 창을 닫은 뒤에도 부모 창이
유지됨을 검사했다. 정식 앱에서는 중복 New 명령의 창 재사용, Cancel과 잘못된 크기 입력의
문서 보존, 성공한 생성 이후의 페인팅·실행 취소·레이어·저장·재열기를 검사했다.

버전 1.0.0 / 빌드 1의 `build/Congregation.app` 하나를 유지한다. 같은 번들을 다른 경로로
옮겨 Metal·Vulkan에서 실행한 뒤 정식 경로로 복원했으며 외부 SDK 라이브러리를 읽지 않았다.
Qt 없는 활성 빌드 그래프·동적 의존성과 ad-hoc 서명을 검증했다.

통합 보고서는 `build/new-canvas/verification.json`, 전체 테스트는
`build/new-canvas/final-tests.xml`과 `final-tests.log`, 빌드는 `final-build.log`에 있다.
새 창의 렌더러별 화면은 `build/new-canvas/native/`와 `vulkan/`에 각각 11장이다.
번들 이동 검사는 `build/native-relocation-verification.json`에 기록한다.
